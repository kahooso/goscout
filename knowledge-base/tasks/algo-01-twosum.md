# Algo-01: Two Sum

## Задание

Дано: слайс `nums []int` и `target int`.
Найди: индексы `i, j` (i != j) такие что `nums[i] + nums[j] == target`.

Сигнатура: `func TwoSum(nums []int, target int) (int, int, bool)` — третий `bool`
сигнализирует «нашли пару». Если не нашли → `0, 0, false`.

Файл: `cmd/tasks/twosum/twosum.go` + `twosum_test.go`.

---

## Моё решение

`map[int]int` (число → индекс). Один проход по слайсу:
- compute `complement := target - nums[i]`
- если complement уже в мапе → возврат `(m[complement], i, true)`
- иначе → положить `m[nums[i]] = i`, идём дальше

Ключевая идиома — **сначала поиск, потом insert**. Если положить раньше — получишь
баг с одним индексом дважды (когда `nums[i] == complement` для самого себя).

---

## Ошибки и трудности

### Главные

1. **Путал ключ и значение мапы.** Сначала думал `map[int]struct{}` где ключ — индекс.
   Не работает: чтобы найти complement (число) в такой мапе пришлось бы перебирать всю.
   Правильно: ключ = число, значение = индекс. Тогда `m[complement]` за O(1).
   Связь: мапа в Go — это `key → value`, понятие «индекс» только у слайсов/массивов.

2. **Возврат `(0, 0)` для случая «не нашли».** Неотличим от валидного ответа.
   Решение — третий `bool` (паттерн comma-ok как у `m[k]` и каналов).

3. **`&& vs ||` в условии теста.** Написал:
   ```go
   if v1 != tc.v1 && v2 != tc.v2 && ok != tc.ok { ... }
   ```
   `&&` — тест падает только если ВСЕ значения неправильные. Если хоть одно совпало —
   тест проходит, баг скрыт. Правильно: `||` — упасть если ХОТЬ ОДНО не совпало.
   Заметил сам пока читал моё ревью — хороший сигнал.

### Минор

- `else` после `return` — лишнее. Идиоматично писать без else.
- `m[36] = nil`? Нет: для `map[int]int` отсутствующий ключ → `0` (zero value), не nil.
  Чтобы отличить от валидного 0 — comma-ok: `v, ok := m[k]`.

---

## Что бы сделал иначе

- Сразу comma-ok при возврате (третий `bool`) — это **дефолт** для функций которые
  могут «не найти». Запомнить как идиому.
- Описательные имена test cases. «андер/булдыр/бойдер» — мусор. Должно быть
  «happy / duplicates / no pair». Тест-имена пишутся для диагностики на CI.
- Имена полей в test struct: `v1, v2` → `wantI, wantJ` (это **индексы**, не значения).
- `return` после первого `t.Errorf` — чтобы не словить два сообщения от одного fail.

---

## Ключевые паттерны

- **`map[T]int` как индекс** — позволяет за O(1) ответить «видел ли я это значение?
  и если да — где». Применимо к Two Sum, Contains Duplicate, Group Anagrams, etc.
- **Третий `bool` в возврате** — `(result, found bool)` для функций которые могут
  не найти. Идиома уровня `comma-ok`.
- **Гейт `tc.ok && ...` в тестах** — проверять «мусорные» поля только когда
  контракт их гарантирует. Защищает от ложных провалов при рефакторинге.
