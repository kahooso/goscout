# Map как индекс — паттерн O(N) поиска

## TL;DR

Когда нужно искать «было ли это значение раньше? где?» — `map[T]int` хранит
число (или другой ключ) → индекс/счётчик. Превращает O(N²) перебор в O(N).

## Где разобрано подробно

- LeetCode проблемы: Two Sum, Contains Duplicate, Group Anagrams, First Unique Char
- Тузов: «Как на самом деле устроен тип Map в Golang? Golang под капотом» (34 мин)
- Идея универсальная — есть в любом языке (Python dict, C++ unordered_map, Java HashMap)

## Базовая форма

```go
seen := make(map[int]int)   // число → индекс (или счётчик)

for i, v := range nums {
    if idx, ok := seen[v]; ok {
        // v уже встречалось, его индекс был idx
    }
    seen[v] = i              // запомнить текущий
}
```

## Two Sum — каноничный пример

Наивный O(N²): два вложенных цикла, сравниваем суммы пар.

Через map за один проход O(N):

```go
func TwoSum(nums []int, target int) (int, int, bool) {
    m := make(map[int]int)
    for i, v := range nums {
        complement := target - v
        if idx, ok := m[complement]; ok {
            return idx, i, true
        }
        m[v] = i
    }
    return 0, 0, false
}
```

**Ключевая логика:** для каждого `v` спросить «видел ли я раньше `target - v`?».
Если да — пара найдена. Если нет — запомнить текущее.

**Критический порядок:** сначала поиск, потом insert. Если положить раньше — для
`v == target/2` найдёшь сам себя (один индекс дважды).

## Когда работает

| Задача | Что хранит map |
|--------|----------------|
| Two Sum | `m[число] = индекс` |
| Contains Duplicate | `m[число] = struct{}{}` (set: достаточно факта присутствия) |
| First Unique Character | `m[char] = частота`; второй проход найти первую с частотой 1 |
| Group Anagrams | `m[sorted_key] = []string` (sorted строка → группа) |
| Subarray Sum Equals K | `m[prefix_sum] = частота` |

Общая идея: **«за O(1) спросить про прошлое»**. Без map — приходится перебирать.

## Подвохи

- **Ключ vs значение.** В мапе нет «индекса». Ключ — то по чему ищем (хеш-таблица
  внутри). Если ключ = индекс слайса — поиск по значению будет O(N), смысл потерян.
- **Zero value vs ключа нет.** `m[k]` для `int` вернёт `0`, не nil. Чтобы отличить
  «не было» от «было и равно 0» — обязательно `v, ok := m[k]`.
- **Порядок вставки.** Поиск перед insert, не после.
- **Память.** При больших N — map растёт, ~64 байта на элемент. Для миллионов нужно
  думать про cap: `make(map[T]int, expectedSize)`.
