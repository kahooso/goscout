# Хеш-таблица vs Дерево

## Что это

Две разные структуры данных для хранения пар ключ→значение с принципиально разными компромиссами.

---

## Хеш-таблица

### Как работает

Массив "корзин" (buckets). Хеш-функция превращает ключ в индекс корзины.

```
"hello" → hash() → 2491 → 2491 % 8 = 3 → bucket[3]
"world" → hash() → 8734 → 8734 % 8 = 6 → bucket[6]
"hey"   → hash() → 1847 → 1847 % 8 = 3 → bucket[3]  ← коллизия
```

При коллизии оба элемента хранятся в одной корзине как список (chaining).
Поиск: снова считаешь хеш → идёшь в ту же корзину → перебираешь маленький список.

### Сложность

| Операция | Среднее | Худший случай |
|----------|---------|---------------|
| Поиск | O(1) | O(n) при всех коллизиях |
| Вставка | O(1) | O(n) |
| Удаление | O(1) | O(n) |

### Ключевые свойства

- Порядка нет — итерация даёт случайный порядок (поэтому `range` по Go `map` непредсказуем)
- Точный поиск: только по полному ключу
- Prefix search невозможен эффективно — `hash("he")` и `hash("hello")` не связаны математически

### Go map — хеш-таблица

```go
m := make(map[string]int)  // аллоцирует hash-таблицу
m["hello"]++               // hash("hello") → bucket → запись
v := m["hello"]            // O(1) поиск
```

## Дерево (BST, AVL, Red-Black)

### Как работает

Каждый узел: ключ + левый потомок (меньше) + правый потомок (больше).

```
         "hello"
        /       \
      "a"       "world"
        \       /
        "hey" "there"
```

Поиск: сравниваешь с текущим узлом → идёшь влево или вправо. O(log n).
In-order обход всегда даёт отсортированный результат.

AVL и Red-Black — BST с автоматической балансировкой (дерево не вырождается в список).

### Сложность

| Операция | Сложность |
|----------|-----------|
| Поиск | O(log n) |
| Вставка | O(log n) |
| Удаление | O(log n) |
| Range query | O(log n + k) |

---

## Сравнение

|                           | Хеш-таблица          | Дерево                 |
| ------------------------- | -------------------- | ---------------------- |
| Поиск по ключу            | O(1)                 | O(log n)               |
| Порядок                   | нет                  | отсортированный        |
| Prefix search             | O(n) — перебор всех  | O(log n + k)           |
| Range query ("от A до B") | O(n)                 | O(log n + k)           |
| C++ аналог                | `std::unordered_map` | `std::map`             |
| Go встроенный             | `map[K]V`            | нет (нужна библиотека) |

**Важно:** в C++ `std::map` — дерево (red-black), поэтому итерация по нему отсортирована.
В Go `map` — хеш-таблица, порядка нет. Частая ловушка при переходе.

---

## Связь с безопасностью

**Hash flooding / HashDoS** — атака на хеш-таблицу: злоумышленник подбирает входные данные
так, чтобы все ключи попадали в одну корзину (все коллизии). O(1) деградирует до O(n).
Защита: случайный seed для хеш-функции при старте (Go делает это автоматически с Go 1.3).
