# Go runtime и компиляция

## TL;DR

Go-бинарник содержит **рантайм** — код от команды Go, который управляет горутинами, GC,
стеком, defer, panic/recover. В C для этого нужны системные библиотеки или ручной код.

## Где разобрано подробно

- `go.dev/doc/effective_go` — общие принципы
- `pkg.go.dev/runtime` — runtime API (использовать почти не нужно)
- Видео Николая Тузова: «Анатомия Go: Как работает планировщик горутин на самом деле»

## Что входит в рантайм

| Подсистема | Что делает |
|------------|------------|
| Планировщик (GMP) | распределяет горутины на потоки ОС, M:N scheduling |
| Garbage collector | освобождает память автоматически |
| Растущий стек | каждая горутина начинается с 2 КБ, расширяется при нужде |
| `defer` | реализация отложенных вызовов |
| `panic` / `recover` | механика паник |

**Следствие:** Go-бинарник весит ~2–5 МБ даже для Hello World — рантайм уже внутри.

## Аналогия с C

```
C:  препроцессор → компилятор → ассемблер → линкер → бинарник
    рантайм — это libc и системные библиотеки (динамически линкуются)
    управление памятью, треды (pthread), signal handlers — вручную

Go: парсер + type check → SSA → оптимизации → машинный код → статическая линковка
    рантайм вкомпилирован в бинарник (статическая линковка)
    GC, планировщик, defer — встроены, не нужно подключать
```

Команда `go build` делает всё за один шаг.

## GOMAXPROCS

Количество ОС-потоков выполняющих Go-код параллельно. По умолчанию = число логических ядер CPU.
Горутин при этом может быть тысячи — планировщик мультиплексирует их на потоки.

```go
runtime.GOMAXPROCS(2)  // ограничить 2 потоками
runtime.NumCPU()       // сколько ядер видит ОС
runtime.NumGoroutine() // сколько горутин сейчас живо
```

**Подвох:** `runtime.GOMAXPROCS(n)` возвращает **предыдущее** значение, не новое.

## Что такое stdlib

«Стандартная библиотека» — пакеты встроенные в Go: `fmt`, `os`, `strings`, `sort`, `net`, `net/http`
и ~150 других. Импортируются без `go get`, всегда доступны.

**Сторонние пакеты** (`github.com/...`) ставятся через `go get`, прописываются в `go.mod`.

## Личный опыт

### Что я понял не сразу

- **Рантайм ≠ библиотека.** В C++ ты подключаешь pthread/std::thread — это библиотека, она тоже
  компилируется в бинарник. В Go рантайм — это **слой между твоим кодом и ОС**, который ты
  обычно не видишь, но он работает (GC, планировщик). Это объясняет почему `go func(){}()` дешёвый —
  рантайм сам распределит на потоки.
- **Большой бинарник — это нормально.** Hello World в Go — 2 МБ. В C — 16 КБ. Разница в рантайме.
  Это плата за «батарейки включены».
- **Статическая линковка по умолчанию.** Один бинарник запустится на любой Linux с той же
  архитектурой без libc-зависимостей (если не использовать cgo).
