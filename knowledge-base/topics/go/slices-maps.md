# Слайсы и мэпы в Go

## Слайсы

### Что это

Слайс — структура из трёх полей ("заголовок"), хранится на стеке. Данные — в heap.

```
заголовок (стек):          массив (heap):
┌─────────────────────┐    ┌──────────────────┐
│ ptr *T  │ len │ cap │ →  │ [0] [1] [2] ... │
└─────────────────────┘    └──────────────────┘
```

Аналог в C:
```c
int *ptr = malloc(n * sizeof(int));
int len = n;
int cap = n;
```

### Нулевое значение и инициализация

```go
var s []int          // nil slice: {ptr: nil, len: 0, cap: 0}
s = append(s, 1)    // Go аллоцирует массив, возвращает новый заголовок
s = append(s, 2, 3) // append вариативный — несколько элементов сразу
```

Когда `len == cap` и делаешь `append` — Go аллоцирует новый массив ~2x, копирует, возвращает новый `ptr`. Как `realloc` в C.

### Формы пустого слайса — nil vs empty

Все шесть записей ниже — один и тот же тип `[]string`. Отличаются только значения трёх
полей заголовка. Отдельного «типа nil-слайса» не существует.

| запись | `len` | `cap` | `== nil` | `ptr` | `json.Marshal` |
|---|---|---|---|---|---|
| `var a []string` | 0 | 0 | **true** | `0x0` | `null` |
| `[]string(nil)` | 0 | 0 | **true** | `0x0` | `null` |
| `[]string{}` | 0 | 0 | false | `zerobase` | `[]` |
| `make([]string, 0)` | 0 | 0 | false | `zerobase` | `[]` |
| `make([]string, 0, 4)` | 0 | 4 | false | heap | `[]` |
| `make([]string, 4)` | **4** | 4 | false | heap | `["","","",""]` |

- `[]string{}` и `make([]string, 0)` получают **один и тот же указатель** — `runtime.zerobase`,
  общий адрес под все аллокации нулевого размера. Памяти не выделено, но указатель не nil.
- `[]string(nil)` — это обычное **преобразование типа** `T(v)`, как `int64(x)` или `[]byte("abc")`.
  Нужно потому, что `nil` сам по себе нетипизирован и `x := nil` не компилируется. В коде так
  почти не пишут — эту запись выдаёт `%#v`, потому что он печатает валидный Go-синтаксис.
- `make([]string, 4)` — ловушка: это не «пустой на 4», а четыре пустые строки. `append` допишет
  пятым элементом.

**Где разница вообще наблюдаема** — всего три места: `== nil`, `reflect.DeepEqual`,
`json.Marshal`. `len`, `cap`, `append`, `range` работают одинаково на всех формах —
поэтому nil-слайс в Go считается нормальным пустым слайсом и `if s == nil { s = []T{} }`
писать не нужно.

**Идиома:** принимать на вход обе формы, возвращать всегда одну. Проще всего это
обеспечивает `make([]T, 0, n)` в начале функции — тогда ни один путь выхода, включая
досрочный `return` по таймауту, не вернёт nil.

### Варианты типов

| Тип         | Что хранит в массиве    | Аналог в C                           |
| ----------- | ----------------------- | ------------------------------------ |
| `[]string`  | строки (ptr+len каждая) | нет прямого аналога                  |
| `[]*string` | указатели на строки     | `char *arr[]` или `char **arr`       |
| `*[]string` | указатель на заголовок  | нет аналога (в C управляешь вручную) |

### string — не массив символов

`string` в Go — read-only slice байт: `{ptr *byte, len int}`. Иммутабельна — нельзя изменить символ по индексу.

`[N]T` — статический массив, размер фиксирован на этапе компиляции. Аналог `int arr[5]` в C.

### Pre-allocate когда знаешь размер

```go
// медленнее — несколько реаллокаций
var keys []string
for k := range m { keys = append(keys, k) }

// быстрее — один раз выделяем нужный размер
keys := make([]string, 0, len(m))
for k := range m { keys = append(keys, k) }
```

## Мэпы

### Что это

`map[K]V` — указатель на hash-таблицу в heap. Аналог `std::unordered_map<K,V>*` в C++.

```go
var m map[string]int     // nil, указатель ни на что
m = make(map[string]int) // Go аллоцирует hash-таблицу
```

### Нулевое значение

```go
var m map[string]int
v := m["key"]   // ok — вернёт 0 (нулевое значение int)
m["key"] = 1    // ПАНИКА — запись в nil map
```

### Основные операции

```go
counts := make(map[string]int)
counts["hello"]++          // ключа нет → создаётся с нулём, потом +1
counts["hello"] = 5        // явное присвоение
delete(counts, "hello")    // удаление ключа

for word, n := range counts { // перебор всех пар
    fmt.Println(word, n)
}
```

### Порядок не гарантирован

`range` по мэпу каждый раз даёт разный порядок. Чтобы отсортировать — извлечь ключи в слайс:

```go
keys := make([]string, 0, len(counts))
for k := range counts { keys = append(keys, k) }
sort.Slice(keys, func(i, j int) bool {
    return counts[keys[i]] > counts[keys[j]] // по убыванию частоты
})
```

## Подводные камни

- `var s []int` — nil slice, но `append` работает корректно
- `var m map[string]int` — nil map, запись вызовет панику
- `sort.Slice` требует строгое упорядочение: `>=` и `<=` в `less` сломают сортировку
- `make(map[string]int, 0)` — лишний `0`, то же что `make(map[string]int)`

## Ключевые термины (English)

- `slice header` — тройка `{ptr, len, cap}`, то, что реально лежит в переменной
- `nil slice` vs `empty slice` — `ptr == nil` против указателя на `zerobase`
- `capacity` — сколько влезет без новой аллокации; `cap()`
- `pre-allocate` — `make([]T, 0, n)`, когда размер известен заранее
- `type conversion` — `T(v)`, например `[]string(nil)`; не приведение, а преобразование
- `untyped nil` — `nil` без типа; `x := nil` не компилируется
- `hash table` — то, чем является `map` под капотом
