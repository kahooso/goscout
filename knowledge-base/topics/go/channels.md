# Каналы (channels)

## TL;DR
Канал — типизированная очередь между горутинами со встроенной синхронизацией:
*share memory by communicating* вместо общей памяти под мьютексом.

## Где разобрано подробно
- `gobyexample.com/channels`, `/channel-buffering`, `/select`, `/closing-channels`
- `pkg.go.dev/sync` (mutex), `sync/atomic` (атомики)
- видео Николая Тузова: «Как на самом деле устроены каналы в Golang» (41 мин,
  тяжёлое — много про планировщик, можно отложить)

## Минимальный пример
```go
ch := make(chan int)      // unbuffered — рандеву (rendezvous): send ждёт receive
ch := make(chan int, 3)   // buffered — send не блокируется пока буфер не полон

ch <- v                   // send: данные ПО направлению стрелки → в канал
v := <-ch                 // receive: из канала в переменную
v, ok := <-ch             // comma-ok: ok=false если канал закрыт И пуст
close(ch)                 // флаг «отправок больше не будет» (НЕ free, данные ещё читаются)
for v := range ch { ... } // читать пока канал не закрыт

select {                  // «switch по каналам» — кто первый готов
case v := <-ch:    ...
case <-ctx.Done(): ...    // ловим закрытие канала отмены
}
```

## Личный опыт

### Что я понял не сразу
- **Три способа синхронизации, не один.** mutex (замок вокруг любого кода) /
  atomic (неделимая операция над ОДНИМ числом, без блокировки потока, быстрее но
  ограниченнее) / канал (передаём данные вместо общей памяти). До task-07 многопоточности
  в C/Go не трогал — mutex/atomic/race были новыми словами.
- **Атомарная операция = неделимая**, её нельзя застать на середине. Решает ту же гонку,
  что mutex, но только для примитива. Внутри канала рантайм использует atomic для своих
  флагов (uint32) + mutex — отсюда «атомики» в видео Тузова.
- **`close` ≠ `free`.** Не освобождает память и не чистит данные — это флаг «sender
  закончил». Из закрытого канала ещё читаются остатки буфера. Память соберёт GC.
- **Захват в замыкании всегда по ссылке.** В Go 1.22 поменяли не способ захвата, а
  ЧИСЛО переменных цикла: была 1 на весь цикл (→ `3 3 3`), стало по 1 на итерацию (→ `0 1 2`).
  Цена «новой переменной на итерацию» = 0, если переменная не захвачена (escape analysis
  схлопывает в одну ячейку); платится только при захвате — та же цена, что ручной `i := i`.

### На чём попадался
- `task-07`: канал данных `chan string` не совпадал с сигнатурой `chan dnsResult` — решал,
  что течёт по каналу (структура, не строка — иначе теряешь чей результат и была ли ошибка).
- `task-07`: запустил ОДНУ горутину с циклом внутри (последовательно) вместо `go` ВНУТРИ
  цикла (N параллельных). `go` оборачивает один вызов, не весь цикл.
- `task-07`: слил цикл запуска и цикл сбора в один (`for range args { go...; select{} }`) —
  блокировался на каждой итерации, параллельность терялась. Нужно ДВА раздельных цикла:
  сначала запустить все горутины, потом собрать N результатов.
- `task-07`: спутал deadlock и goroutine leak. **Deadlock** = ВСЕ горутины спят, рантайм
  паникует `fatal error`, шумно. **Goroutine leak** = одна горутина повисла навсегда (напр.
  `ch <- res` в unbuffered после ухода получателя), программа работает, рантайм молчит,
  память тихо течёт. Leak опаснее именно тишиной. Чинит buffered-канал на `len(N)`.

### Подводные камни
- `ch <- v` в закрытый канал → **panic**. Из закрытого читать можно (zero value + ok=false).
- `close` делает ТОЛЬКО sender, один раз. Двойной close → panic. Получатель не закрывает.
- unbuffered send в одиночной горутине без receiver → deadlock (`all goroutines asleep`).
- `select` при НЕСКОЛЬКИХ готовых case выбирает **случайно** (анти-starvation). Поймал на
  тесте: закрытый `ctx.Done()` + готовый `ch` = flaky-тест, падал через раз (task-07).
- `select` без `default` блокируется; `default` делает неблокирующим (мгновенный отказ).

## Ключевые термины (English)
- `channel` — типизированная очередь между горутинами
- `unbuffered` / `buffered` — без буфера (рандеву) / с буфером на N
- `rendezvous` — «встреча»: unbuffered send и receive происходят одновременно
- `send` / `receive` — отправка `ch <- v` / приём `v := <-ch`
- `comma-ok idiom` — `v, ok := <-ch`, ok=false если закрыт и пуст
- `race condition` — гонка за общими данными, недетерминированный результат
- `mutex` (mutual exclusion) — замок, один поток в критической секции
- `atomic operation` — неделимая операция, нельзя прервать на середине
- `deadlock` — все горутины заблокированы навсегда
- `goroutine leak` — горутина повисла навсегда, тихая утечка памяти
- `starvation` — голодание: один канал монополизирует, другой не обслуживается
