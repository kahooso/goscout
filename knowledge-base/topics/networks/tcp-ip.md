# TCP/IP — фундамент (для goscout ports)

## TL;DR
Сеть — слоёный пирог: IP адресует **машину**, порт адресует **процесс** на ней,
TCP даёт надёжную доставку поверх ненадёжного IP через установку соединения (handshake).

## Где разобрано подробно
- Книга «Computer Networking: A Top-Down Approach» (Kurose, Ross) — лучший старт
- Книга «TCP/IP Illustrated, Vol.1» (W. R. Stevens) — глубокая классика по пакетам/флагам
- Книга «Computer Networks» (Tanenbaum) — академический учебник (вероятно в универе, сем 4)
- Wireshark — снифер: увидеть живой SYN/SYN-ACK/ACK глазами («Wireshark TCP handshake tutorial»)
- nmap — эталонный сканер портов (goscout ports = маленький самописный nmap)
- См. также reference в memory: `reference_networks_learning.md`

## Слои TCP/IP (4 слоя)

| Слой (англ) | Перевод | Решает | Адресует | Юнит | Примеры |
|---|---|---|---|---|---|
| Application | Прикладной | смысл данных | — | data | HTTP, DNS, SSH |
| Transport | Транспортный | доставка процессу + надёжность | **порт** | segment/datagram | **TCP**, UDP |
| Internet | Сетевой | маршрутизация, доставка хосту | **IP** | packet | IP, ICMP |
| Link | Канальный | физический канал | MAC | frame | Ethernet, Wi-Fi |

**TCP/IP vs OSI:** одно и то же, разная детализация. OSI = 7 слоёв, теория + общий язык
(«проблема L4/L7»). TCP/IP = 4 слоя, практика, по которой реально работает интернет.
Рабочая модель — TCP/IP; OSI-нумерация (L1–L7) знать для собеса.

## Порт vs IP
- **IP-адрес** = адрес машины в сети («какой компьютер»). Дом.
- **Порт** = адрес процесса внутри машины («какая программа»). Квартира. 16 бит → 0–65535.
- `192.168.0.1:8080` = дом 192.168.0.1, квартира 8080.
- **Слушатель (listener)** = программа (процесс), сказавшая ОС «отдавай мне всё с порта N».
  Связка: процесс (sshd) **слушает** порт (22) и **говорит** по протоколу (SSH).
- **Well-known ports** (0–1023, реестр IANA, договорённость): 22 SSH, 80 HTTP, 443 HTTPS,
  3306 MySQL. Это конвенция, не закон — сервис можно посадить на любой порт.

## TCP — надёжность поверх IP
- **IP ненадёжен**: кинул пакет — не знаешь, дошёл ли (как письмо без уведомления).
- **TCP** — надстройка: доставка + порядок + без потерь. Потерялось → переотправит.
- **Retransmission** (ретрансмиссия) — повтор сегмента, если ACK не пришёл. Backoff
  экспоненциальный, **но с потолком** (`TCP_RTO_MAX` ~120с): паузы 0.2,0.4,...102,120,120...
  После ~15 попыток (`tcp_retries2`) TCP сдаётся → `connection timed out`.
  **Главное:** дефолтный TCP-таймаут = **минуты** → сканеру нужен СВОЙ короткий таймаут.
- **TCP vs UDP:** TCP = заказное письмо (гарантии, медленнее: HTTP/SSH/БД).
  UDP = открытка (без гарантий, быстрее: видео/звонки/игры/DNS — лучше пропустить
  кадр, чем тормозить ради переотправки).

## Three-way handshake (тройное рукопожатие)
Установка соединения = 3 пакета. Делает **ядро ОС**, не приложение. Проверяет только
факт «есть открытое соединение», содержимого данных НЕ видит.

```
КЛИЕНТ                          СЕРВЕР (слушает :443)
  |  ---- 1. SYN ---------->  |   «хочу соединиться, синхронизируемся»
  |  <--- 2. SYN-ACK ------   |   «согласен (SYN) + подтверждаю твой (ACK)»
  |  ---- 3. ACK ---------->  |   «подтверждаю твоё согласие»
  |  ===== СОЕДИНЕНИЕ =====   |   теперь можно слать данные (уровень Application)
```

Три, т.к. соединение двунаправленное: каждая сторона и заявляет готовность (SYN),
и подтверждает чужую (ACK). Средний пакет совмещает SYN+ACK сервера → 3, не 4.

**Флаги** SYN/ACK/RST/FIN — отдельные **биты** (0/1) в TCP-заголовке, читает сетевой
стек ОС. Комбинируются: SYN-ACK = оба бита = 1. Это НЕ CLI-флаги (--timeout) — те строки
для пакета flag, эти — физические единички в бинарном заголовке.

## Сканирование порта — три исхода (ключ к goscout ports)
Сканер шлёт SYN, смотрит реакцию. Данных НЕ шлёт — нужен только факт «слушает ли кто-то».

| Реакция на SYN | Вывод | В Go (DialTimeout) |
|---|---|---|
| **SYN-ACK** (handshake пошёл) | **OPEN** — есть слушатель | `conn, nil` |
| **RST** (reset, «обрыв») | **CLOSED** — никто не слушает | `nil, err` (connection refused) |
| **тишина** (ни SYN-ACK, ни RST) | **FILTERED** — firewall дропнул | `nil, err` (timeout) |

**Firewall (брандмауэр)** — фильтр перед портами. Реакция на SYN:
- **allow** → пропустил к ядру → дальше OPEN (SYN-ACK) или CLOSED (RST), зависит от слушателя
- **reject** → вежливый отказ: RST / ICMP «port unreachable». Ошибка быстро.
- **drop** → молча проглотил, тишина → FILTERED. Защита через неопределённость:
  атакующий не понимает open/closed/dropped, тратит время на таймауты.

**ICMP** (Internet Control Message Protocol) — служебный протокол сетевого слоя для
ошибок/диагностики (не данных). На нём работают `ping` и `traceroute`.

## Личный опыт

### Что я понял не сразу
- **`net` ≠ `gin`.** `net` = низкий уровень (сырые TCP/UDP-сокеты, как POSIX
  `socket()`/`connect()`/`read()`). `gin` = высокий уровень (HTTP-фреймворк) поверх
  `net/http` поверх `net`. Спускаемся на дно — туда, где живёт сканер портов.
- **SYN-ACK ≠ «приложение приняло мои данные».** Handshake (ядро ОС, уровень TCP)
  и данные (приложение, уровень Application) — разные уровни. Порт OPEN ⇔ handshake
  прошёл; корректность данных, которые пошлёшь ПОТОМ, на открытость не влияет.
  Пример: `telnet host 80` → handshake ОК → печатаю мусор → сервер шлёт 400.
  Дверь открылась, что сказал внутри — отдельная история. Сканер до данных не доходит.
- **Backoff с потолком.** Чистое `2^15` секунд (=9 часов) — неверно: backoff упирается
  в `TCP_RTO_MAX ~120с`, дальше полка. ~15 попыток ≈ ~15 минут. Цифра не для зубрёжки,
  важно «дефолтный таймаут = минуты → нужен свой».

### Подводные камни
- Без своего таймаута на FILTERED-порте connect висит минуты (ждёт RST/SYN-ACK,
  которые не придут) → goroutine leak (связь с A0.6). Отсюда `net.DialTimeout`.

## Ключевые термины (English)
- `three-way handshake` — SYN → SYN-ACK → ACK, установка TCP-соединения
- `SYN / ACK / RST / FIN` — биты-флаги в TCP-заголовке (synchronize/acknowledge/reset/finish)
- `listener` — процесс, слушающий порт
- `well-known ports` — общеизвестные порты 0–1023 (реестр IANA)
- `retransmission` — переотправка сегмента при отсутствии ACK
- `open / closed / filtered` — три состояния порта при сканировании
- `firewall` — `allow` / `reject` / `drop` (drop = тишина = filtered)
- `ICMP` — Internet Control Message Protocol (ошибки/диагностика, ping/traceroute)
