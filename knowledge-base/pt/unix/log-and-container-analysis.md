# Анализ логов и Docker-форензика (кейсы 1.10, 1.13)

Переносимые ИБ-навыки из двух кейсов главы 1: чтение логов безопасности и извлечение секретов
из слоёв Docker-образа. Не пересказ методички — только то, на чём споткнулся и что усвоил.

---

## Кейс 1.10 — анализ логов аутентификации

**`auth.log` — первое место для ИБ:** попытки входа и привилегированные действия. Неудачные
входы по SSH: `grep "Invalid user" /var/log/auth.log`.

### На чём попадался
- **`grep: binary file matches`** вместо строк. Значит совпадение есть, но grep увидел не-текстовый
  байт и подавил вывод. Лечится `grep -a` (читать как текст). Молчание grep тут ≠ «пусто».
- **Свои же команды в выдаче.** `sudo` пишет каждую команду в `auth.log`; мой `sudo grep 'Invalid user'`
  содержал искомую строку → grep ловил сам себя. Сужать до сервиса: `grep -a "sshd.*Invalid user"`.
  Отличить своё от атаки помогает формат времени: сгенерированные события `Jun 22` (без года,
  классический syslog) vs живые `2026-…T…+03:00` (ISO/RFC3339).
- **Размер `/var/log/journal`:** `du -h` дал `185M`, чекер не принял → верно `184M` из
  `journalctl --disk-usage`. `du` = место на диске (округляет по блокам), `journalctl` = учёт самого
  journald. Живой журнал растёт (в т.ч. от твоих команд) — мерить непосредственно перед ответом.

### Security-угол
**Log injection** — атакующий подмешивает в логируемое поле (username, User-Agent) управляющие
байты или переводы строки, чтобы сломать парсер аналитика, спрятать строку сдвигом вывода или
подделать соседние записи. Аналитик, который знает про `-a`/`cat -v`, видит спрятанное.

## Кейс 1.13 — контейнеры и форензика слоёв

**Базовое:**
- `docker exec -it <c> sh` — оболочка внутри контейнера; `docker exec <c> <cmd>` — разовая команда.
- `cd config` дал `Not a directory` → `/etc/config` это ФАЙЛ, читать `cat`, не `cd`.
  (`Not a directory` ≠ `No such file`: первое — «есть, но файл», второе — «пути нет».)
- `docker history [--no-trunc] <img>` — слои = хронология сборки, читать снизу вверх. `0B` = слой
  метаданных (`ENV`/`CMD`, файлы не добавляет); `<missing>` в ID — норма для базовых слоёв.

**Форензика удалённого секрета (главное):**
Образ = стопка неизменяемых слоёв. Файл, вырезанный в позднем слое (`rm`), **остаётся в том слое,
где его добавили** — верхний слой лишь прячет его в финальной ФС (whiteout). Значит секрет из
«удалённого» файла достаётся из архива образа. Раз `docker save` пишет слои **несжатым tar'ом**,
искать можно прямо grep'ом, не распаковывая:
```sh
docker save <img> | grep -a "api_key"                # поток образа → grep как текст
# или, если распаковал: grep -ra "api_key" <распакованный_архив>/
```

**На чём попадался:**
- Грепал **не тот образ**: `app_config` (= `example-image`, alpine+ENV, 8.42MB) секрета не содержал —
  его история вообще без `COPY config.ini`. Пустой grep по всему архиву = «строки нет», а не «сломалось».
- Смещение подозрений на `company-api` и **`<none>` dangling-образ** — осиротевшая промежуточная
  стадия сборки, классическое место, где выживает удалённый секрет. Поиск по всем: цикл `docker images -q`.
- Мелкие промахи ввода: незакрытая кавычка (шелл ушёл в `>`), `grep` без пути, слишком строгий
  шаблон `-o` (`=[...]*` мимо `key = value` с пробелами). Правило: сначала грепай широко, чтобы
  УВИДЕТЬ формат, потом сужай.

### Security-угол
`COPY secret` + `RUN rm secret` **НЕ убирает секрет** из образа — он в истории слоёв. Правильно:
build secrets (`--secret`), переменные при запуске, multi-stage build (секрет в отбрасываемой стадии).
`docker history --no-trunc` + `docker save | grep` — стандартный приём аудита образов на утечки.

## Ключевые термины (English)

- **auth.log** — журнал аутентификации и привилегированных действий (Debian)
- **log injection** — внедрение управляющих символов/переводов строк в логируемые поля
- **`grep -a` / `--text`** — читать «бинарный» файл как текст (снять подавление вывода)
- **journald / `journalctl --disk-usage`** — бинарный журнал systemd и его собственный учёт размера
- **image layer** — неизменяемый слой образа = изменения ФС на одном шаге сборки
- **whiteout** — пометка в слое, скрывающая файл из нижних слоёв (удаление ≠ стирание данных)
- **dangling image** (`<none>`) — осиротевший промежуточный образ/стадия сборки
- **`docker save`** — выгрузка образа со слоями и метаданными в tar (слои несжатые)
- **build secret / multi-stage** — способы не оставить секрет в финальном образе
