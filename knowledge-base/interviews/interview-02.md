## Уверенно знает (все 3 уровня)
- **Интерфейсы (A0.7)** — зачем (убирают дублирование у ПОТРЕБИТЕЛЯ — один `runProbe` вместо
  `runProbeDNS`/`runProbePorts`), неявная реализация (тип и интерфейс не знают друг о друге,
  соответствие по набору методов), где именно проверяет компилятор (точка присваивания
  интерфейсу, не определение типа; ошибка `does not implement ... (missing method)`).
  Держится сам, без подсказок. Тема, которая раньше давалась трудно, — закрыта.
- **Числовая vs лексикографическая сортировка (A0.9)** — посимвольное сравнение слева направо
  до первого различия; `"80" < "8080"` по префиксу. Объяснил сам, привёл свой пример (81/86).
- **close канала + worker pool (A0.9)** — после разбора: зачем `close(jobs)` (сигнал воркерам
  «данных больше не будет» → `range` завершается; иначе воркеры виснут на пустом открытом
  канале), идиома «закрывает отправитель и только один», почему `results` НЕ закрывает,
  panic на send в закрытый (ответил верно), read из закрытого можно.
- **io.Reader как параметр (A0.8)** — развязка от источника, тестируемость через
  `strings.NewReader` вместо временного файла (механику теста пришлось напомнить).
