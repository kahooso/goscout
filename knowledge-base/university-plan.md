# Учебный план — синхронизация с goscout

**Специальность:** 10.03.01 Информационная безопасность, бакалавр.
**Профиль:** `_06` — **Безопасность компьютерных систем (Технологии искусственного
интеллекта в кибербезопасности)**.

> Это карта тем универа для синхронизации. Универ = **контекст** (какие темы сейчас в потоке),
> не драйвер направления. Работа с Claude = **практика**: те же темы пишу руками на Go, без нейронки-за-меня.
> goscout = **якорный продукт** с ближней целью (сетевой recon CLI с security-уклоном), растёт
> по мере тем. AI/ML — вне roadmap goscout. Карьерный вектор держится вне этого репозитория.
> Модель — `.claude/CLAUDE.md`, вехи — `strategy/learning-strategy.md`.

## Точки естественного совпадения: универ ↔ практика в goscout

> Это **точки естественного совпадения** тем универа и goscout, **не график и не дедлайн**.
> Где совпало по времени — пользуюсь синергией; где нет — иду по вектору, не подгоняя проект
> под расписание семестра. Колонка «Практика на Go» — ориентир, что разумно делать на Go рядом
> с темой, а не обязательство к сроку.

| Семестр | Универ даёт (теория) | Практика на Go (руками) | Эффект |
|---------|----------------------|--------------------|--------|
| **2 (сейчас)** | Структуры данных, Основы ИБ | A0-фундамент Go + algo-задачи на Go | Структуры данных на втором языке → на экзамене свои |
| **3** | Языки прогр., ОС (старт), матан | Закончить A0, старт `goscout: сети` (DNS, ports) | К ОС приходишь, понимая процессы/таймауты из практики горутин |
| **4** | **Компьютерные сети**, ООП, реверс | сетевое ядро goscout (≈v0.1) — если совпадёт по времени | Совпадут сети в универе с сетевым ядром — двойное усиление (не дедлайн) |
| **5** | **Основы ИИ**, Сети (зачёт), Технологии ПО | HTTP probe / TLS / security headers (≈v1) — по мере тем | Совпадёт с зачётом по сетям — усиление; AI входит как тема универа |
| **6** | Модели безопасности, компиляторы, крипта | Интеграция goscout / мини-инструмент | Закрепление |
| **7** | **Безопасность сетей**, AI Security трек, агентные системы | по факту — решу ближе к делу (goscout не зашит под AI) | теория универа; в проекты — если сам захочу |
| **8** | **Безопасность ОС, СУБД, ML в кибербезе, детект через AI** | по факту — специализация решается тогда, не сейчас | теория универа; ML-проект — отдельное осознанное решение |

## Что из этого следует для стратегии

1. **goscout (сетевой scout) естественно совпадает с семестром 4 «Компьютерные сети» — точка
   синергии, не дедлайн.** Выбор сетей как темы якоря — не случайность: это ближайший крупный
   профильный блок + личный интерес.
2. **Алго-задачи синхронны с «Структурами данных» (сем 2, сейчас).** Не redundant —
   универ даёт теорию (на C), практика на Go закрепляет её.
3. **Linux/ОС — ждём универ (сем 3-4).** Сейчас Linux трогается косвенно через goscout
   (бежит на Linux, CI на Linux, сетевые сисколлы). Глубоко — когда универ даст ОС.
4. **AI/ML — НЕ конечная точка goscout.** Универ даёт ИИ с сем 5 и ML-безопасность в сем 7-8
   (факт программы — сдам как предметы). Будет ли ML в моих проектах — решу позже, отдельно;
   в goscout сейчас не закладываем.
5. **Криптография — большая универ-линия (сем 5-6-8) + сильная математика.** В практику goscout
   пока не тянем; появится естественно, когда универ даст основы (возможно TLS в HTTP probe).

## Чего НЕ переносим в практику на Go (оставляем универу)

- Чистая математика (высшая, дискретка, ТВиМС, теоретико-числовые методы) — теория универа.
- Реверс-инжиниринг, электроника, схемотехника — есть в программе, но не вектор
  (reverse/kernel неинтересны). Сдаём, не делаем pet-проект.
- Правовое/организационное обеспечение, этика — теория универа.
