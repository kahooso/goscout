## Главный вектор

**Дорога:** product / infra / deep-tech backend на Go. Двигатель — «создавать новое».
**Кибербезопасность — сильный сквозной угол** и реальная точка входа (стажировка AppSec /
Security Go; Positive — реальный план), один из путей, не единственная узкая цель.
**Сейчас специализацию не выбираю — строю фундамент Go.** Решу позже, по факту
(Positive → больше security; Avito/Ozon/Яндекс → широкий backend).

> Карьерный вектор держится отдельно от учебного плана и здесь не переписывается —
> см. `CLAUDE.md` → «Вектор-вопросы — здесь не решаются».

**Модель: университет даёт теорию (контекст тем), работа со мной = практика на Go руками.**
- Универ показывает, какие темы сейчас в потоке: структуры данных → сети → ОС → крипта → AI-security.
  Это контекст (что под рукой), не драйвер — направление задаёт вектор.
- Я беру тему **по своему вектору**, синхронизируя с тем, что универ даёт сейчас, и пишу руками
  **на Go**, без нейронки-за-меня.
- **Ритм: вектор ведёт, универ синхронизирует.** Где вектор и универ совпали по теме — пользуюсь
  совпадением. Не убегать в совсем чужое (Rust/kernel — не мой путь), но и не ждать универ,
  если вектор ведёт вперёд.

**Точки естественного совпадения с семестрами:** [university-plan.md](../university-plan.md).

## Якорный продукт: outpost (ближняя цель + открытый рост)

> outpost — **не «полигон», а продукт с названной БЛИЖНЕЙ целью**: это снимает паралич
> «не знаю формы». Но дальний горизонт открыт — продукт **растёт вместе со мной**, без воды
> и без привязки к календарю универа. Каждая веха — реально на GitHub.

Репозиторий: `github.com/kahooso/outpost` (`Desktop/outpost`), вынесен из goscout 2026-07-28.

**Ближняя форма:**
**Сетевой recon / диагностический CLI на Go с security-уклоном.**
Сканирует сеть (DNS / порты / HTTP / TLS), показывает что открыто / как настроено / где небезопасно.
Это прикладная безопасность в виде работающего кода — синергит с профилем ИБ и с CTF-треком.

**Дорожная карта (вехи, без привязки к семестрам):**

| Веха | Что умеет | Статус |
|------|-----------|--------|
| **v0.1** | dns + ports, README, тесты, CI | dns и ports работают; до тега — 3 пункта `BACKLOG.md` |
| **v1.0** | + HTTP probe, TLS-анализ, security headers | зрелый сетевой инструмент |
| **дальше** | открыто — по мере тем и интереса (service detection? CVE-check? своё) | растёт со мной |

**AI/ML — вне roadmap outpost.** Захочу ML → отдельный осознанный проект, не «потому что
дипломный профиль». **Сейчас:** блок A0 закрыт, продукт доводится до тега v0.1.

## Принципы

1. **Проект раньше теории** — пишем `outpost`, темы изучаем как фичи для него.
2. **Теория раньше кода** — три фазы (концепция → пакет → контрольные вопросы) обязательны до задания.
3. **Одна задача = одна тема** (+ фича продукта, если задача продуктовая). Не смешивать больше.
4. **Каждая задача → тесты** — минимум 3 кейса: happy + граничный + злой. Для concurrency — `-race`.
5. **Каждая задача → vault** — иначе знание не зафиксировано.
6. **Каждые 8 задач — мок-собес** по пройденным темам.
7. **Не уверен в теме — закрепление, не следующая.**
8. **Скучно — говорить сразу.** Не тянуть нелюбимую тему ради галочки.
9. **Длинные комментарии в коде → vault.** В `sections/**/*.go` остаётся только что объясняет именно этот фрагмент.
10. **Algo-практика — параллельная ветка** (см. ниже). Не заменяет основной план A0/A/B, но
    вкрапляется между задачами для закрепления базы и тренировки собеседовательного формата.
11. **English-словарь** — каждая новая запись в `topics/` имеет раздел
    `## Ключевые термины (English)`. Названия функций/пакетов/протоколов — всегда на английском.
    Это словарь для собесов (PT, Яндекс, Bi.Zone) и чтения RFC/доков. Детали — в принципах ниже.
12. **CTF — параллельный трек** (picoCTF, фокус Web + General). Практика AppSec руками,
    синергия с OWASP Top 10. Инициирует только пользователь. Детали — в скилле `ctf` и разделе ниже.
13. **Подача — ступенями по одной.** Работать в ЕГО коде, не давать оторванных примеров
    в вакууме. БЕЗ аналогий C/C++ и слова «труба» (memory `feedback_teaching_style`).
    Просит ОБСУДИТЬ подход — сначала разговор, а не прогон команд.

## CTF-практика — параллельная ветка

**Зачем:** security / AppSec — один из твоих путей и профиль универа. CTF (picoCTF) — это практика
безопасности **руками**, под атакующим углом. Не для накопления флагов, а чтобы
OWASP Top 10 был из опыта, а не из статьи, и чтобы набить рабочий словарь утилит.

**Фокус — веб и приложения, не reverse/pwn/forensics.** Поэтому:
- **Главное:** Web Exploitation (SQLi, XSS, SSRF, IDOR, JWT) + General Skills.
- **Можно:** лёгкая крипта (base64/XOR/Caesar).
- **Пропускать:** reverse, pwn, тяжёлую крипту, stego — не вектор (и неинтересно по CLAUDE.md).

**Темп:** 1–2 челленджа в неделю, 60–90 мин. Цель-ориентир: 30+ к концу 2026.
Инициирует **только пользователь** — счётчиков нет, проактивно не напоминать.

**Хранение:** `knowledge-base/ctf/picoctf/` (сессии + writeup'ы по категориям).
Каждый web-writeup привязан к OWASP-категории. Детали процедуры — скилл `ctf`.

**Синергия с goscout:** сетевые/HTTP-челленджи прямо пересекаются с будущей командой
`goscout http` (security headers, TLS). Сначала понять руками что заголовки защищают.

## English — рабочий технический словарь

**Зачем:** собесы в PT / Яндекс / Bi.Zone / Kaspersky и чтение RFC, доков, CVE — на английском.
Цель — выстроить технический словарь через регулярное использование, не отдельным курсом.

**Правила:**
- Каждая новая запись в `topics/` имеет раздел `## Ключевые термины (English)` — глоссарий темы.
- Названия функций, пакетов, флагов, типов — **только английский**, не транслитерировать
  (`context.WithTimeout`, `DialTimeout`, `race condition`, не «дайлтаймаут»).
- Ключевые концепции при первом упоминании в объяснении — англ. термин + русский в скобках:
  «состояние гонки (race condition)», «таймаут контекста (context timeout)».
- Старые `topics/` не переписывать массово — глоссарий добирается естественно при редактировании.

Это правило исполняется через скилл `vault-write` (шаблон `topics/` содержит раздел глоссария).

## Логика выбора следующей задачи

```
1. Открыть roadmap/00-roadmap.md → «Текущая позиция»
2. Счётчик ≥ 8 → предложить мок-собес (скилл mock-interview)
3. Иначе → следующая тема активного блока
   блок не расписан по заданиям → скилл plan-block
4. Спросить уверенность в предыдущей теме
   неуверен → задача-закрепление
5. Три фазы → задание → тесты → разбор в task-файле рядом с кодом
```

Процедура мок-собесов и blank-slate ретестов — скилл `mock-interview`,
фиксация — `knowledge-base/interviews/`.
