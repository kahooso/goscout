## Принципы

1. **Проект раньше теории** — не "учу HTTP", а "пишу security scanner". Инструмент — мотивация.
2. **Go везде** — все задачи пишутся на Go, кроме явных исключений.
3. **Теория раньше кода** — фаза 1–2 (концепция + пакет) обязательна ДО задания.
   Без понимания внутреннего устройства задание выдавать нельзя.
4. **Одна тема — один task** — не смешивать горутины и SQL injection в одном задании.
5. **Каждая задача завершается тестом** — минимум 1–2 table-driven теста на функцию.
6. **Каждый task завершается vault-записью** — иначе знание не зафиксировано.
7. **Раз в 8 задач — мок-собес** — по пройденным темам, формат вопрос-ответ без кода.
8. **Не уверен в теме — закрепление, не следующее** — если пользователь сомневается,
   следующая задача по той же теме на чуть более сложном примере.
9. **Скучное — говорить сразу** — если тема неинтересна, обсудить, не тянуть.
10. **DevSecOps-вкрапления** — раз в 5–8 задач можно подкинуть короткую D-задачу
    (gosec на свой код, GitHub Actions для go vet, написать gitignore и т.п.) —
    щупать направление параллельно, не уходя из основной линии.

Нужен перед сетевыми задачами. Изучить язык Go с нуля — структуры, слайсы, указатели, горутины, каналы, интерфейсы, ключевые пакеты.

**Формат каждого задания в A0 (обязательно):**

3. **Контрольные вопросы** — 3–5 вопросов, по одному, дождаться ответа
4. **Задание** — только после трёх фаз
5. **Тесты** — минимум 1–2 table-driven теста; пакет `testing` объясняется параллельно

#### A0.3 — Указатели
Цель: понять когда и зачем нужны указатели в Go, разница между value receiver и pointer receiver.
Задание: написать изменяемый стек (`Push`, `Pop`) — без указателей не заработает; объяснить почему.
Код: `cmd/pointers/`
Бонус (по желанию после основного): реализовать односвязный список (`Append`, `Remove`, `Print`) —
чистая практика указателей, каждый узел содержит `*Node`. Хорошо видна разница `*T` vs `T` на практике.

#### A0.4 — Обработка ошибок
Цель: Go-way работы с ошибками — `errors.New`, `fmt.Errorf` с `%w`, `errors.Is`, `errors.As`.
Задание: написать функцию парсинга конфига из строки, которая возвращает кастомные типизированные ошибки.
Пакеты: `errors`, `fmt`
Код: `cmd/errors-demo/`
Бонус (по желанию): реализовать простую хеш-таблицу вручную — массив корзин, хеш-функция,
разрешение коллизий через chaining (`[]Entry`). Связь с безопасностью: hash flooding как DoS-атака.

#### A0.5 — Горутины
Цель: понять что такое горутина, как она запускается, как дождаться завершения.
Задание: запустить N горутин, каждая выводит своё сообщение, main дожидается всех через `sync.WaitGroup`.
Пакеты: `sync.WaitGroup`
Код: `cmd/goroutines/`

#### A0.6 — Каналы
Цель: передача данных между горутинами без shared state.
Задание: producer–consumer через канал; buffered vs unbuffered; `close` + `range`; `select`.
Код: `cmd/channels/`

#### A0.7 — Context и таймауты
Цель: управление lifecycle горутин — отмена и дедлайн.
Задание: запустить горутину с `context.WithTimeout`, которая делает "медленную работу" и прерывается по таймауту.
Пакеты: `context`
Код: `cmd/context-demo/`

#### A0.8 — Интерфейсы
Цель: понять неявную реализацию интерфейсов в Go; `io.Reader`/`io.Writer` как главные примеры.
Задание: написать свой тип, реализующий `io.Writer`, передать его в `fmt.Fprintf`.
Пакеты: `io`, `fmt`
Код: `cmd/interfaces/`

#### A0.9 — Ключевые пакеты stdlib
Цель: уверенно работать с os, bufio, strings, errors — они нужны в каждом инструменте.
Задание: читать файл построчно через `bufio.Scanner`, фильтровать строки по паттерну, выводить результат.
Пакеты: `os`, `bufio`, `strings`
Код: `cmd/stdlib-demo/`

### Блок B — AppSec основы [после A3–A4]

#### B1 — OWASP Top 10
Цель: знать топ уязвимостей веба, уметь объяснить каждую своими словами.
Формат: для каждой из 10 — что это, пример уязвимого кода, как защититься в Go.
Практика: WebGoat (Docker) — пройти задания по теме.
Vault: `topics/security/owasp-top10.md`

#### B2 — SQL Injection
Цель: понять SQLi глубоко — как уязвимость и как детектировать.
Задание: Go SQLi detector — анализирует HTTP-параметры URL на наличие паттернов инъекции.
Пакеты: `regexp`, `net/http`
Код: `cmd/scanner/`

#### B3 — XSS, CSRF, SSRF
Цель: разобрать три самых частых веб-уязвимости.
Формат: теория + практика на WebGoat + добавить проверки в свой scanner.
Vault: `topics/security/xss.md`, `topics/security/csrf.md`, `topics/security/ssrf.md`

#### B4 — Auth уязвимости: JWT и сессии
Цель: понять как ломают авторизацию.
Задание: Go-инструмент для анализа JWT токенов — decode без библиотеки, проверка alg=none, expired.
Пакеты: `encoding/base64`, `encoding/json`
Код: `cmd/`

#### B5 — Broken Access Control и IDOR
Цель: понять горизонтальное и вертикальное повышение привилегий.
Формат: теория + WebGoat + добавить проверку в scanner (предсказуемые ID в URL).

#### B6 — Финал: HTTP Security Scanner v1
Объединить A5, B1–B5: один инструмент который по URL выдаёт security-отчёт.
Проверяет: headers, TLS версию, признаки SQLi в параметрах, JWT анализ если есть токен.
Место: `cmd/scanner/http-scanner/`

## Карьерная стратегия (обновлено 2026-04-25)

### Основная цель: AppSec инженер / Security Go Developer

**AppSec инженер:** находит и закрывает уязвимости в коде и инфраструктуре. Делает code review с security фокусом, настраивает SAST/DAST, обучает разработчиков.
**Security Go Developer:** пишет инструменты безопасности — сканеры, агенты, детекторы. Близко к разработке, но с security контекстом.

Оба пути ценятся. Первые 1–2 года обучения общие, специализация проявится сама.

Что НЕ нравится: ручной пентест, red team, reverse engineering — эти направления не включать в план без явного запроса.

### Точка входа: Junior AppSec / Security Go developer intern (2–3 курс, ~2026–2027)

**Что это:** встраивание безопасности в разработку — code review, SAST, тестирование безопасности API.
**Компании:** Positive Technologies, Bi.Zone, Яндекс (безопасность продуктов), Kaspersky (разработка), Сбер (продуктовая безопасность).
**Что ищут:** умеет читать/писать Go, знает OWASP, понимает HTTP/TLS, может найти SQLi в коде.

### Важно

DevSecOps — стартовая площадка, не конечный пункт. Если окажется интересно — углублять. Если нет — оставить как базовый навык.
fn2s roadmap продолжается параллельно с любой стажировкой.
