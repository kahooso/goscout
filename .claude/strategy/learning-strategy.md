## Принципы

1. **Проект раньше теории** — пишем `goscout`, темы изучаем как фичи для него.
2. **Теория раньше кода** — три фазы (концепция → пакет → контрольные вопросы) обязательны до задания.
3. **Одна задача = одна фича scout + 1–2 темы.** Не смешивать больше.
4. **Каждая задача → тесты** — минимум 3 кейса: happy + граничный + злой. Для concurrency — `-race`.
5. **Каждая задача → vault** — иначе знание не зафиксировано.
6. **Каждые 8 задач — мок-собес** по пройденным темам.
7. **Не уверен в теме — закрепление, не следующая.**
8. **Скучно — говорить сразу.** Не тянуть нелюбимую тему ради галочки.
9. **Длинные комментарии в коде → vault.** В `cmd/*.go` остаётся только что объясняет именно этот фрагмент.
10. **Algo-практика — параллельная ветка** (см. ниже). Не заменяет основной план A0/A/B, но
    вкрапляется между задачами для закрепления базы и тренировки собеседовательного формата.
11. **English-словарь** — каждая новая запись в `topics/` имеет раздел
    `## Ключевые термины (English)`. Названия функций/пакетов/протоколов — всегда на английском.
    Это словарь для собесов (PT, Яндекс, Bi.Zone) и чтения RFC/доков. Детали — в принципах ниже.
12. **CTF — параллельный трек** (picoCTF, фокус Web + General). Практика AppSec руками,
    синергия с OWASP Top 10. Инициирует только пользователь. Детали — в скилле `ctf` и разделе ниже.

## Algo-практика — параллельная ветка

**Зачем:** закрепление базы знаний (slices/maps/pointers/strings) через мини-задачи
в формате собеседования. Это **не** новая большая тема — это «пятиминутки на удержание
формы». Параллельно основной линии A0/A/B.

**Когда вкраплять:**
- Когда пользователь говорит «дай алго-задачку», «давай LeetCode», «хочу размяться»
- Когда после задачи A0 осталось 30–60 минут сессии и брать новую тему рано
- Когда после мок-собеса видны пробелы по базовой теме — алго-задача на этом паттерне
- Не чаще ~1 algo-задачи на 2–3 задачи блока A0 — не отвлекать от основной линии

**Где хранить:**
- Код: `cmd/tasks/<имя>/<имя>.go` + `<имя>_test.go` (пакет = имя задачи, не `main`)
- Запись: `knowledge-base/tasks/algo-NN-<имя>.md` — отдельная нумерация
- Паттерн (если новый): `knowledge-base/topics/algo/<паттерн>.md`

**Тематический бэклог** (когда давать какую):

| # | Задача | Паттерн | Когда уместно |
|---|--------|---------|----------------|
| algo-01 | Two Sum | map-as-index | ✅ выполнено (2026-05-17) |
| algo-02 | Contains Duplicate | map-as-set | базовый разгон после Two Sum |
| algo-03 | Valid Anagram | map подсчёт частот | после strings/maps |
| algo-04 | Reverse Linked List | указатели + рекурсия/итерация | после A0.3 закрепления указателей |
| algo-05 | Move Zeroes | two-pointers | новый паттерн |
| algo-06 | Longest Substring Without Repeating | sliding-window | средний уровень, после A0.6 |
| algo-07 | Group Anagrams | map[string][]string | средний уровень |
| algo-08 | Top K Frequent Elements | map + sort или heap | связь с sort.Slice |

Не давать все подряд. Выбирать в зависимости от того где пробелы или интерес.

**Формат сессии под algo-задачу (~30–60 мин):**
1. Постановка (1–2 мин) — задача коротко, сигнатура, пример
2. Сократовский разговор про подход (5–10 мин) — наивный O(?) → оптимальный
3. Пользователь пишет код + тесты (~20 мин)
4. Code review через скилл `code-review`
5. Запись в `tasks/algo-NN.md` через `vault-write`

**Чего НЕ делать:**
- Не давать алго вместо темы A0 если пользователь явно не попросил
- Не превращать в марафон по LeetCode — это **закрепление**, не основная цель
- Не делать алго с темой которую пользователь ещё не проходил (например graph BFS до интерфейсов)

## CTF-практика — параллельная ветка

**Зачем:** security / AppSec — один из твоих путей и профиль универа. CTF (picoCTF) — это практика
безопасности **руками**, под атакующим углом. Не для накопления флагов, а чтобы
OWASP Top 10 был из опыта, а не из статьи, и чтобы набить рабочий словарь утилит.

**Фокус — НЕ как у fn2s.** Друг (builder СЗИ) приоритезирует reverse/pwn/forensics.
У тебя цель — веб и приложения, поэтому:
- **Главное:** Web Exploitation (SQLi, XSS, SSRF, IDOR, JWT) + General Skills.
- **Можно:** лёгкая крипта (base64/XOR/Caesar).
- **Пропускать:** reverse, pwn, тяжёлую крипту, stego — не вектор (и неинтересно по CLAUDE.md).

**Темп:** 1–2 челленджа в неделю, 60–90 мин. Цель-ориентир: 30+ к концу 2026.
Инициирует **только пользователь** — счётчиков нет, проактивно не напоминать.

**Хранение:** `knowledge-base/ctf/picoctf/` (сессии + writeup'ы по категориям).
Каждый web-writeup привязан к OWASP-категории. Детали процедуры — скилл `ctf`.

**Синергия с goscout:** сетевые/HTTP-челленджи прямо пересекаются с будущей командой
`goscout http` (security headers, TLS). Сначала понять руками что заголовки защищают.

### A0.6 — каналы + context (объединённая тема)

**Почему вместе:** каналы без context = неполное знание; в реальном Go горутины,
каналы и context всегда вместе.

**Фича в scout:** `goscout dns <domain1,domain2,...> --timeout 5s`
- запускает N горутин-резолверов (по одной на домен)
- каждая пишет результат в канал
- main собирает результаты через `select { case <-results: ... case <-ctx.Done(): ... }`
- `context.WithTimeout` останавливает зависшие горутины

**Пакеты:** `sync` (уже знаком), `context`, встроенные каналы.
**Что нового по сравнению с task-06:** `select`, `close(chan)`, `range ch`, `context.WithTimeout`.

### A0.7 — интерфейсы

**Фича в scout:** ввести интерфейс `Probe`:
```go
type Probe interface {
    Run(ctx context.Context, target string) (Result, error)
    Name() string
}
```
Реализации: `DNSProbe`, заглушка `PortProbe`. Регистрация в main через слайс `[]Probe`.

**Что нового:** неявная реализация интерфейсов, `io.Reader`/`io.Writer` как главные примеры stdlib.

### A0.8 — stdlib (os, bufio, flag)

**Фича в scout:** флаги `--wordlist file.txt`, `--timeout`, чтение wordlist построчно через `bufio.Scanner`.

**Пакеты:** `flag` (или `os.Args` для начала), `os`, `bufio`, `errors`.

### A0.9 — net пакет (TCP/DialTimeout)

**Фича в scout:** команда `goscout ports <host> --ports 80,443,22,8080`.
- параллельный TCP DialTimeout
- worker pool через буферизованный канал

**Пакеты:** `net.DialTimeout`, `net.JoinHostPort`.

**Итог:** v0.1 готов. Дальше — пересмотр плана.

## Что после A0

> Не планируем сейчас. Когда `goscout` v0.1 заработает — садимся, смотрим что выучили,
> где пробелы, и что хочется добавить (HTTP probe? TLS analysis? Service detection?
> CVE check?). Стратегия пишется задним числом по реальному состоянию, не вперёд по фантазии.

Карьерные ориентиры (контекст, не план; детально по карьере — goagent):
- **Сейчас**: фундамент Go (A0) + algo; `goscout` v0.1 (dns+ports) на GitHub с тестами и CI.
- **Сети (сем 4)**: сетевое ядро goscout синергит с предметом — двойное усиление.
- **Дальше**: goscout v1 (HTTP/TLS), CTF web-челленджи; стажировка (~2027) — AppSec/Security Go
  **или** широкий backend, решается по факту.
- Глубже 2 курса детально не планируем — см. goagent.
