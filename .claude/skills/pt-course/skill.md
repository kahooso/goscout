# Скилл: pt-course

Ведение основного трека — модуль PT EdTechLab «Введение в кибербезопасность»
(63 кейса, 4 теста, 86 часов, 6 недель). Владеет **циклом темы** и **гейтом закрытия темы**.

Трекер прогресса: `knowledge-base/pt/00-progress.md` — **primary source** для этого скилла.
Не путать с `give-task` (задания по Go из блока) и `theory` (разбор кода по теории).

## Цикл темы — 5 шагов

### 1. Якоря (перед чтением)

Пользователь называет тему → выдать **4–6 вопросов**, ответы на которые он должен
найти в материале платформы. Не пересказ, не спойлер — только вопросы.
Цель: превратить чтение из скольжения глазами в поиск ответов.

Якоря должны цеплять **механику**, а не термины: не «что такое initramfs»,
а «почему ядру недостаточно драйверов, которые уже в нём есть».

### 2. Чтение (он, самостоятельно)

Читает оригинал платформы. Claude в этом шаге не участвует.
**Не пересказывать материал курса** — он написан экспертами и уже есть у пользователя.
Расширенный пересказ = второй слой чтения с худшим удержанием.

### 3. Разбор непонятого

Пользователь присылает **конкретный фрагмент + свой вопрос** (не всю статью).
Разбирать глубоко и — где возможно — **прогоном на его виртуалке**, а не словами
(стандарт доказательства, memory `feedback_think_independently`).

У курса есть лабораторные VM (Debian, Windows, стенды) — это главное преимущество.
Отвечать по возможности так: «выполни эти команды и посмотри, что получилось».

Пример (BIOS/UEFI): `ls /sys/firmware/efi`, `lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT`,
`findmnt /boot/efi`, `cat /proc/cmdline`, `systemctl get-default`.

**Если фрагмент вне лабы** (Windows AD без стенда, чужая инфраструктура) — разбирать
словами + схемой, но явно помечать «это не проверено руками».

**Инфраструктуру стенда Claude может чинить сам — двумя уровнями доступа** (выведено на стендах
1.11 и 1.9, 2026-09-16..18). VM крутятся в VirtualBox на Windows пользователя.

- **Host-side (по умолчанию):** через PowerShell доступен `VBoxManage` (обычно
  `D:\Program Files\Oracle\VirtualBox\VBoxManage.exe`). Чинит сеть/загрузку стенда:
  `list natnetworks`, `natnetwork modify --network`, `modifyvm --natdnshostresolver1 on`,
  `controlvm acpipowerbutton/poweroff`, `startvm`. Канал проверяется без пароля — снятием
  SSH-баннера сырым TCP на host-порту проброса.
- **Guest-side (по явной просьбе + пароль):** если пользователь застрял на инфра-баге,
  настойчиво просит «сделай за меня» и сам даёт пароль — Claude заходит по SSH в гостя.
  Неинтерактивный пароль на Windows OpenSSH (≥8.4) — через `SSH_ASKPASS`-хелпер (`.cmd`,
  echo пароля) + `SSH_ASKPASS_REQUIRE=force`; `sudo` — `echo '<пароль>' | sudo -S -v` (прогреть),
  дальше `sudo` без `-S`. **Обязательно после: удалить файл-хелпер с паролем и сказать сменить
  пароль** (он светился в чате). Приёмы — `knowledge-base/pt/network/lab-networking.md`.

**Когда guest-side уместно, а когда нет.** Заходить и делать за пользователя — только если
блокер это **баг стенда/среды, а не его навык**, и сам зачётный конфиг он уже собрал верно
(прецедент 1.9: 4/5 проверок зелёные его руками, валил мёртвый DNS в NAT VBox — обойдён пином
в `/etc/hosts`). **Не** запускать зачётный чекер за него, если он ещё не сделал саму задачу —
это его работа и его токен. Токены/пароли/решения стендов в vault не коммитить (публичность).

**Первым делом — сырой вывод, не пересказ.** `VBoxManage`, `netstat`, `getent`, `ip a` —
факты; «всё окей» за эту сессию много раз прятало реальную причину (опечатка `198`/`192`,
дубль профиля NM, мёртвый DNS). Проси показать, а не подтвердить.

**Известные грабли VBox-стендов — перебирать ПЕРВЫМИ, до своих гипотез** (выведено на 2.7 VLAN,
где Claude две ночи не вспоминал пункт 1; наводку дал пользователь):
1. **Promiscuous Mode = Deny (дефолт)** — мост/switch-ВМ не форвардит unicast: **broadcast-шторм идёт,
   а пинг между узлами 100%.** Лечится `Allow All` на всех адаптерах мостов; L3-роутеру НЕ нужен.
   Якорь: голый «IP на ether» работает, мост — нет. Memory `reference_vbox_mikrotik_promisc`.
2. **Горячая правка адаптера НЕ применяется** — `controlvm nicN intnet <name>` / `nicpromisc` на живой
   ВМ не встают на работающий адаптер; нужен **power-cycle** (poweroff→startvm), не guest `reset`.
3. **Дубль/опечатка адреса** (`.1` вместо `.3`, `10.0.10` vs `10.0.0`) — memory `feedback_manual_transcription_typos`.
4. **Смещение нумерации `ether` у клонов** (ether2/3/4 вместо 1/2/3 — имена привязаны к MAC) — сверять по MAC.
5. **Адаптер на дефолтном `intnet`** вместо нужного линка; **DHCP-клиент не на том интерфейсе** (`*2`≠`ether3`).
6. **Кириллический омоглиф в пути конфига** (русская раскладка) — `dlopen`/`open` падает `No such file` при
   ЖИВОМ файле, `ldd`/`file` чисты. Извлекай путь ИЗ конфига (`awk`/`grep`) и `ls` его; `grep -nP '[^\x00-\x7F]'`
   на скрытую кириллицу. Memory `feedback_manual_transcription_typos` (выведено на 2.9 OpenVPN, стоило часов).
7. **Профиль VM под ОС — ставить тип ОС правильно СРАЗУ** (выведено на 2.17 OPNsense, ~ночь боли). Дефолтный
   «Other/Unknown» даёт 64 МБ RAM / 32-бит / нет APIC / PCnet-карты, и каждая настройка ломает свой этап загрузки
   по очереди: мало RAM (не грузится) → 32-бит (`CPU doesn't support long mode`) → нет APIC (`panic: requires a
   local APIC`) → PCnet (`Am79C973`→`le0` вместо `em`). Фикс: `modifyvm <vm> --memory 2048 --cpus 2 --ostype
   FreeBSD_64 --longmode on --ioapic on --nictype 82540EM`. ⚠️ Смена `--ostype` **СБРАСЫВАЕТ `--nictype`** — ставить
   nictype ПОСЛЕ ostype. ISO не отцепить на живой VM (`VERR_PDM_MEDIA_LOCKED`) → poweroff → `storageattach
   --medium emptydrive` (иначе грузится в live-режим, пароль `opnsense`). Диск с установкой переживает переконфиг
   VM — проверять размер `.vdi` перед тем как переставлять (уцелел → вернуть адаптеры, а не ставить заново).

**Дисциплина отладки (провал Claude на 2.9, держать жёстко):** перед утверждением о причине запустить
**дешёвый решающий чек** (`ldd`/`strings`/`tcpdump -X`/`file`) и проверять значение, **извлечённое из источника**,
а не набранное руками — перепечатка «чинит» баг на время теста. Факты противоречат сообщению → спускайся слоем
ниже (ENOENT на живой файл ≠ «файла нет»: это загрузчик/LSM/чужой namespace/скрытый символ). Не деструктивничать
по кругу (`ip addr flush` + слетающая статика съели часы) — на DHCP-интерфейсе `restart networking` смывает ручной `ip addr add`.

**Attack-лабы (MITM: 2.11 ARP, 2.12 DHCP — паттерн под будущие кейсы атак/веба):**
- жертва **спамит флаг** постоянно (UDP на `8.8.8.8:<порт>`, у 2.11/2.12 — `12345`, тело `TOKEN: <flag>`) — ищи
  ПОВТОРЯЮЩИЙСЯ пакет; фильтровать `tcpdump` по **MAC** жертвы (IP при DHCP скачет), MAC берётся host-side (`showvminfo`);
- **держать Victim ВЫКЛЮЧЕННОЙ, пока атака не армирована** (starvation выгреб пул + rogue поднят) → включить, и она
  стартует в отравленную сеть без гонки за старый адрес. Это чистый проход, снимает всю боль с перехвата DHCP;
- **брать РОВНО тот образ Victim из методички** — переиспользование чужого (тут ARP-лабы, hostname `debian-lab-arp`)
  = нет флаг-спама, был корневой блокер всей сессии 2.12;
- MITM: `ip_forward=1` + `send_redirects=0` (иначе атакующий ICMP-редиректом сам сливает жертву на прямой путь мимо себя);
- флаг-байты сверять **hex-дампом** (`tcpdump -X`), не `strings` (склеивает 2 байта соседнего пакета); арбитр — `length` пакета.

**Host-side трейд трафика** (сильный приём этой сессии): `VBoxManage debugvm <vm> statistics --pattern
"/Drivers/IntNet-*/Packets/*"` даёт per-port приём/передачу — двумя замерами считается pps и видно, по
какому линку кадр идёт и где умирает (так локализованы шторм и односторонний unicast). Консоль можно
вести самому: `keyboardputstring` + scancode Enter (`1c 9c`), Ctrl-C = `1d 2e ae 9d`.

### 4. Recall — гейт темы

5–7 вопросов на **воспроизведение**, не на узнавание. Отвечает письменно, своими
словами, без подглядывания в материал. Claude находит дыры и называет их прямо.

Форма вопросов recall:
- «объясни цепочку X → Y, где рвётся, если убрать Z»
- «дана ситуация N — порядок диагностики»
- «почему сделано так, а не иначе»
Не спрашивать определения — определения узнаются, а не воспроизводятся.

**Тема закрыта (✅) только после сданного recall.** Прохождение guided-кейса
статусом закрытия не является: guided-формат даёт иллюзию компетентности.

### 5. Конспект — пишет ПОЛЬЗОВАТЕЛЬ, Claude ревьюит

Только для тем приоритета **A**. Файл `knowledge-base/pt/<глава>/<тема>.md`
своими словами. Claude разбирает его как код: неточность, пробел, неверная модель —
указать место и спросить «что здесь не так», не переписывать за него
(та же ветка B из скилла `code-review`).

Шаблон конспекта — `.claude/templates/` (при отсутствии: механика → как проверить
руками → чем это ломается / где уязвимо → `## Ключевые термины (English)`).

## Темп закрепления — правила, выведенные из сессии 2026-09-02

**Задачи на модификацию давать ПО ОДНОЙ, не списком.** Список из пяти задач был выдан
после кейса 1.4: сделано четыре, на пятой — «устал, напиши код». Одна задача → проверка →
следующая. Список целиком показывать можно только как карту, если пользователь сам просит
увидеть объём.

**Конспект — один на главу, не на кейс.** По одному кейсу конспект слишком мелкий и
воспринимается как повинность. Отложенные ⏸ темы собираются в общий файл главы.

**Признак усталости — сменить режим немедленно.** Триггеры: «впадлу», «устал»,
«напиши код», «не понял, давай ты». Реакция: готовый код или прямое объяснение с
пошаговым разбором, БЕЗ наводящих вопросов и без «попробуй ещё». Объём подсказок в
следующей задаче не урезать (memory `feedback_think_independently`, раздел «Аварийный выход»).

**Копирование готового кода из кейса не создаёт памяти.** Пользователь сам это
сформулировал: «обучение хорошее, но на практике слишком быстро улетучивается». Поэтому
закрепление по теме A = модификация рабочего кода своей рукой, а не перечитывание кейса.

## Банк вопросов и повторение (введено 2026-09-06)

Файл `knowledge-base/pt/recall-bank.md` — накопительный список вопросов на воспроизведение.
Причина существования: кейс 1.5 дал 7/7 на платформе и 3/7 в recall через час.
Guided-формат проверяет узнавание, спрашивать будут воспроизведение.

**Разминка — в начале КАЖДОЙ сессии, до нового материала.** 3 вопроса, ~5 минут.
Порядок выборки: сначала ❌, затем ✅ старше двух недель, затем 🔲 из закрытых тем.
Вопрос из кейса, пройденного в прошлую сессию, не брать — он ещё в оперативной памяти.

**Шафл-тест — при закрытии главы.** 10–12 вопросов вперемешку по всей главе, без
группировки по кейсам: смешение тем и есть проверяемый навык.

**Провал recall не переигрывается в тот же день.** Разобрать ошибки → занести вопросы
в банк с пометкой ❌ → вернуться через интервал. Повторный прогон сразу после разбора
измеряет краткосрочную память, а не удержание.

**Проваленная тема на векторе (AppSec/Go) поднимается до A.** Прецедент: «цепочка доверия
apt → GPG → supply chain» поднята с B до A по итогам recall 1.5. Провал в теме, которая
почти наверняка будет на собеседовании, важнее исходного приоритета кейса.

**Термин спрашивается явно.** В recall 1.5 выводы были верные, а слова — нет
(«репозиторий» вместо «локальные индексы»). Поэтому в вопрос закладывается требование
назвать точное место/имя: не «где хранится», а «какой файл и чем отличается от соседнего».

## Калибровка — правило, выведенное из кейса 1.6 (2026-09-06)

**«Мне эта тема даётся легко» — сигнал усилить recall, а не сократить его.** Прецедент:
заявление о лёгкости, затем 0/8. Уверенность в этом треке пока обратно связана с результатом.

**Различать тренажёр и проверку.** Часть чекеров платформы (напр. `perm-lab` в 1.6) сообщает
об ошибках и выдаёт подсказки по ходу. Такой формат не отличает «знал» от «подобрал по
подсказке», поэтому «пройден с первой попытки» о знании не говорит ничего. При фиксации
статуса указывать, был ли чекер с обратной связью.

**Если несколько вопросов провалены с одной причиной — чинить модель, а не факты.**
В 1.6 три разных провала (выбор тройки, удаление чужого файла, происхождение прав нового
файла) свелись к одному: «право проверяется не на том объекте». Разбор строить вокруг
общей причины, иначе пользователь заучит три частных случая.

**Вопросы «почему так сделано» ставить обязательно.** Механику пользователь пересказывает,
инженерное обоснование — нет. На собеседовании спрашивают именно второе.

## Приоритеты A / B / C

Раскладка по темам — в трекере. Правило применения:

- **A** — полный цикл (5 шагов).
- **B** — шаги 1, 2, 4 (recall устно, конспект не пишем).
- **C** — шаг 2, отметка в трекере. Разбор только если сам споткнулся.

**При дефиците времени режется глубина B/C, не количество A.**
Тема A не пропускается никогда — переносится, но не выпадает.

## Связь с Go-треком

Курс не отменяет вектор. Где тема курса пересекается с outpost — предлагать
короткую Go-вставку (DNS, TCP/IP, порты, HTTP, TLS, security headers, разбор логов).
Формат: не полноценный task, а 20–40 строк за одну сессию. Код — в репозиторий
outpost, разбор — в `knowledge-base/tasks/`.

Фоновый режим Go на время курса: **1 короткая сессия в неделю** (решение 2026-08-30).
Ближайшая цель — довести outpost до тега `v0.1` (O2, O4–O7 в roadmap).

## Правило публичности

goscout публичный. В vault идут **конспекты своими словами**.
НЕ коммитить: тексты статей и кейсов платформы копипастом, задания и решения стендов,
учётные данные, адреса лабораторной инфраструктуры, VPN-профили.
Если пользователь прислал такой материал в чат — использовать для разбора,
но не сохранять дословно в файл.
