# Скилл: lecture

Цель — чтобы после сессии пользователь **сам** мог объяснить тему (на экзамене, на защите). Не пересказ лекции преподавателя, а спроектированное объяснение с проверкой.

**До действия:** [`TEACHER.md`](../../TEACHER.md), профиль `lecture`. По умолчанию — простой язык (§2), академический режим (§7) — только если попросили «академично» / «как лекцию с источниками».

## Триггеры

- `/lecture`, `/lecture <тема>`, «объясни лекцию N», «разбери тему X», «прочитай лекцию по X».
- Передача из `study` (режим «разобрать тему»).

Работает и для Go/PT, если попросили именно лекцию: тогда источники — `knowledge-base/topics/` и `knowledge-base/pt/`.

## Алгоритм

### 1. Тема и цель

Не названы — один открытый вопрос: «Какая тема, зачем (экзамен / лаба / задачи / интерес), есть ли файл лекции?». Цель задаёт акцент:

| Цель | Акцент |
|---|---|
| Экзамен / зачёт | определения и формулировки как в курсе, типовые вопросы, «почему» |
| Задачи | какие типы задач тема даёт и какой метод к какому типу (дальше — `problems`) |
| Лаба | механизм + как это видно в лабе, что понадобится при выполнении |

### 2. Материалы

По приоритету:
1. Лекция преподавателя: `C:\Users\ryche\Desktop\gostudy-materials\<N>-semester\<предмет>\` (путь к файлу — в трекере предмета). Опора — **формулировки и обозначения курса**: на экзамене спросят их.
2. Свой конспект: `university/<N>-semester/<предмет>/lectures/`. Есть — не дублировать, а назвать: «перед началом стоит перечитать `lectures/03-…md`» и углублять.
3. Учебник курса (если известен), затем веб. Ссылаться только на реально открытое.

### 3. Проектирование (молча)

По `TEACHER.md` §2: ядро в 2 предложения → список понятий (что уже есть в конспектах, что новое) → порядок по зависимостям → где нужен пример с числами, где путаемая пара → разбивка на блоки, ≤ 3 новых термина в блоке.

### 4. План — и стоп

Показать: ядро (2 предложения) + блоки по одной строке + откуда материал. Спросить: «так идём? что-то поменять?». Ждать подтверждения. Правки плана — до начала, не после.

### 5. Объяснение по блокам

**Один блок за ответ** (`CLAUDE.md` гейтинг). Структура блока:
1. Зачем (какую проблему решает) — 1–2 строки.
2. Суть словами, на примере с числами.
3. Формулы — plain-text, каждая буква расшифрована.
4. Если есть путаемая пара — таблица.
5. В конце — **один** вопрос на вывод по этому блоку (не «понятно?»), затем «есть вопросы? дальше?».

Ответ пользователя на вопрос — разобрать коротко: верно / где дыра. Дыра → доразобрать до следующего блока.

Режим «одним сообщением» — только если пользователь сам попросил (тогда лекция целиком = один блок, гейт после неё).

### 6. Teach-back

После последнего блока: «расскажи тему своими словами, как на экзамене — 5–7 предложений, не подглядывая». Разобрать: что верно, что пропущено, где неточная формулировка. Пропущенное — короткий доразбор, не повтор лекции.

### 7. Фиксация

1. Вопросы в `recall.md` предмета: 3–6 штук по теме (на воспроизведение и «почему»), плюс всё, на чём ошибся в шаге 5–6 (с ❌).
2. Предложить конспект `lectures/NN-<тема>.md`. Формат: ядро → разделы по блокам → формулы с расшифровкой → типичные ошибки → `## Ключевые термины (English)`. Абзац — одной строкой (Obsidian сам переносит). **Кто пишет:** по умолчанию Claude пишет каркас, пользователь дописывает «своими словами» раздел «Как я это понимаю» — так конспект работает на память. Если пользователь не хочет — пишет Claude, но teach-back из шага 6 тогда обязателен.
3. Строку в трекер (`README.md` → «Лекции / темы») и в `journal.md`.

## Чего не делать

- Не начинать без согласованного плана.
- Не вываливать всю тему одним сообщением без просьбы.
- Не пересказывать конспект, который уже есть, — ссылаться и углублять.
- Не придумывать источники и обозначения: в курсе обозначают так, как в лекции преподавателя.
- Не превращать ответ на уточняющий вопрос в новую лекцию (1–2 абзаца).
