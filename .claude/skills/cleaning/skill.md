# Скилл: cleaning

Сам находит мусор в инструкциях проекта: дубли, противоречия, битые ссылки, пережитки, личные данные в публичных файлах. Согласует каждое решение с пользователем и только потом правит. (Перенесён из bedrock-knowledge.)

Не путать с [`refactor`](../refactor/skill.md): `refactor` меняет структуру по замыслу пользователя, `cleaning` ищет проблемы сам. Правки — по инвариантам `refactor`.

**Тон:** `CLAUDE.md`.

## Скоуп по умолчанию

- `.claude/`: `CLAUDE.md`, `TEACHER.md`, `CODESTYLE.md`, `HOWTO.md`, все `skills/*/skill.md`;
- память: `~/.claude/projects/c--Users-ryche-Desktop-goscout/memory/`;
- трекеры: `knowledge-base/roadmap/00-roadmap.md`, `knowledge-base/pt/00-progress.md`, `university/*/*/README.md` — только ссылки и упоминания правил/скиллов, не содержание плана;
- анонимность: весь индекс git.

Конспекты и код не править — только проверять ссылки в них.

## Алгоритм

1. **Прочитать скоуп целиком.** Противоречие видно только при чтении обоих мест, не по grep-выдержкам.
2. **Механика (скриптом, вывод показать):**
   | Проверка | Как |
   |---|---|
   | Пути в тексте существуют | пути в backticks и markdown-ссылках → `test -e` |
   | Wikilinks резолвятся | `[[name]]` → файл `name.md` или memory с `name:` |
   | Упомянутые скиллы существуют | → `.claude/skills/<name>/` |
   | Реестр скиллов полон | каждая папка `skills/*` есть в таблице `CLAUDE.md` и в профилях `TEACHER.md` §0 |
   | Анонимность | `.githooks/pre-commit`-логика по `.anon-map` на `git grep --cached`; плюс поиск ФИО/групп/email в неотслеживаемых md, которые могут попасть в git |
3. **Смысл:** дубли правил (источник истины подачи — `TEACHER.md`, Go-стиля — `CODESTYLE.md`); противоречия между файлами; пережитки (удалённые скиллы, папки, решения); устаревшие таблицы «чем отличается от соседей»; память, дублирующая `CLAUDE.md`/скиллы; строки `MEMORY.md` без файла и файлы без строки.
4. **Отчёт без правок:** таблицы от серьёзного к мелкому — утечки личных данных → противоречия → битые ссылки и пережитки → дубли → мелочи. Каждый пункт: `file:line`, суть, предлагаемое действие.
5. **Согласование через AskUserQuestion**, до 4 вопросов за вызов. Противоречие — отдельный вопрос («верно A» / «верно B» / «убрать правило»). Механика — один multiSelect. Удаление — всегда отдельное явное «да».
6. **Правки** с каскадом: удалён скилл → реестр `CLAUDE.md`, профиль `TEACHER.md` §0, упоминания в других скиллах; удалена память → строка `MEMORY.md` и все `[[slug]]`.
7. **Проверка:** grep по каждому удалённому имени → 0 совпадений, вывод привести. Коммит — бриф по memory `feedback_commit_style`.

## Чего не делать

- Не править до согласования; не удалять без явного «да» на пункт.
- Не трогать содержание конспектов, плана и кода.
- Не оставлять «починю позже»: каскад доводится до 0 совпадений в той же сессии.
