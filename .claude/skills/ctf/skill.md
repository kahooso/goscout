# Скилл: ctf

Параллельный трек: регулярные CTF-сессии на picoCTF.
Цель — практика инфобеза под **AppSec-угол**: видеть веб/приложение глазами атакующего,
закрепить OWASP Top 10 руками, набрать material для собесов и резюме.

Это **не** основная линия A0/A/B. Параллельный трек ~60–90 мин на сессию.

---

## Платформа

**picoCTF** — образовательная CTF-платформа от Carnegie Mellon University.
- play.picoctf.org/practice — бесплатно, регистрация открытая.
- Есть постоянные таски (picoGym) и сезонные события.
- Каждое задание = найти **flag** в формате `picoCTF{...}`.

### Категории и приоритет ДЛЯ AppSec (не как у fn2s)

| Категория | Что качает | Приоритет для тебя |
|-----------|-----------|--------------------|
| **Web Exploitation** | SQLi, XSS, SSRF, IDOR, JWT, command injection, cookies | **Главный** — это и есть AppSec |
| **General Skills** | Linux CLI, base64, file, grep, git, простые скрипты | Высокий — разогрев + рабочий словарь утилит |
| **Cryptography** | base64/XOR/Caesar → потом RSA/AES | Средний — base/XOR полезны, тяжёлую крипту пока пропускать |
| **Forensics** | strings/xxd, Wireshark, метаданные, stegano | Низкий — кроме сетевой части (pcap синергит с goscout) |
| **Reverse / Pwn** | objdump, GDB, ассемблер, stack/heap | **Пропускать** — это не вектор (reverse/kernel неинтересны по CLAUDE.md) |

**Приоритеты сейчас:**
1. **General Skills** — закрыть быстро, набить руку на утилитах.
2. **Web Exploitation Easy** — основной фокус, прямая синергия с OWASP Top 10.
3. **Cryptography** только base64/XOR/Caesar — лёгкое, остальное на потом.

Reverse, Pwn, тяжёлую крипту, stego — **не предлагать** пока сам не запросит.
Это согласуется с твоим security-углом (AppSec — один из путей), а не с низкоуровневым reverse.

---

## Зачем CTF в стратегии goscout

Security / AppSec — один из твоих путей (и профиль универа). CTF здесь для:

1. **OWASP Top 10 руками** — прочитать про SQLi мало; надо хоть раз самому вытащить
   данные через инъекцию, чтобы на собесе говорить из опыта, а не из статьи.
2. **Рабочий словарь утилит** — `curl`, `base64`, `jwt_tool`, `grep`, dev-tools браузера,
   Burp/`ffuf` позже. AppSec-инженер живёт в этих инструментах.
3. **Атакующий угол на свой же код** — пишешь `goscout http` с разбором security headers?
   Сначала пойми руками, что эти заголовки защищают.
4. **Материал для резюме и собеса** — решённый Web-челлендж с writeup'ом = конкретная
   история «что я делал», а не «читал про XSS».

CTF — **не критический путь**. Если долго не зовёшь — это твоё решение, не повод напоминать.

## Триггеры

Счётчиков **нет**. CTF инициирует **только пользователь** — сам следит за темпом
(ориентир 1–2 челленджа в неделю, цель 30+ к концу 2026).

Прямые запросы: «дай ctf», «хочу picoctf», «ctf-сессия», «давай web-челлендж».

`give-task` CTF **не предлагает** проактивно.

## Алгоритм

### 1. Прочитай контекст

- `.claude/strategy/learning-strategy.md` → «Текущая позиция» (для уровня).
- `knowledge-base/00-roadmap.md` → раздел `## CTF` — журнал решённых тасков
  (чтобы не предлагать повторно).
- `knowledge-base/ctf/picoctf/` — структура writeup'ов, если нужны детали.

### 2. Подбери категорию под уровень и цель

- По умолчанию — **General Skills** (если совсем разогрев) или **Web Exploitation Easy**.
- Web-таск с SQLi/XSS уместен даже сейчас — теория OWASP не требует пройденного Go.
- Не предлагать Reverse/Pwn/тяжёлую крипту.

### 3. Сформулируй задание

```
Платформа: picoCTF (play.picoctf.org/practice)
Категория: <General Skills / Web Exploitation>
Сложность: Easy (Medium когда Easy закрыты)
Количество: 2–3 таска за сессию
Время: 60–90 минут
```

**Конкретные таски не назначаем** — пусть выберет сам в категории и сложности.
Причина: задачи на picoCTF меняются, плюс важна привычка читать и выбирать из списка.
Если просит конкретику — указать **тип** («задача на SQLi-логин», «задача на JWT none-alg»),
а не имя таска.

### 4. Создай файл сессии

`knowledge-base/ctf/picoctf/session-NN.md`:

```markdown
---
session: NN
platform: picoctf
date: YYYY-MM-DD
category: <категория>
difficulty: <Easy/Medium>
status: in-progress
---

# CTF Session NN — <дата>

## Цель сессии
<категория, сколько тасков, на чём фокус>

## Решённые таски
*(заполняется после)*

## Нерешённые / частично
*(заполняется после — это важнее)*

## Новые инструменты / приёмы
*(флаги утилит, payload'ы, неожиданные решения)*

## Связанные темы
*(wikilinks на topics/security/)*
```

### 5. После сессии — разбор

Когда возвращаешься с результатами:
- Какие таски решил, на каких застрял.
- На каждый решённый — короткий вопрос «что было ключевой идеей?» (техника, не флаг).
- На нерешённые — где упёрся. Hint = **направление**, не payload
  («проверь, фильтрует ли форма кавычку», а не «вот строка инъекции»).

Для каждого нетривиального таска — отдельный writeup:

`knowledge-base/ctf/picoctf/<category>/<task-name>.md`:

```markdown
---
task: <picoCTF task name>
category: <категория>
difficulty: <уровень>
date: YYYY-MM-DD
solved: true|false
owasp: <A03 Injection / A07 ... — если web>
---

# <Task Name>

## Условие
<краткое описание>

## Подход
<как думал, что пробовал>

## Решение
<команды / payload / запрос>

## Что узнал нового
<главное — техника, инструмент, идея>

## Связь с реальным AppSec
<какая OWASP-категория, как это защищают в проде>

## Ключевые термины (English)
<глоссарий — `SQL injection`, `parameterized query`, `same-origin policy`, `JWT claim` и т.д.>
```

Затем `vault-write` создаёт/обновляет связанную `topics/security/<тема>.md`
(например `topics/security/sql-injection.md`).

### 6. Обнови журнал

Добавить строку в раздел `## CTF` в `knowledge-base/00-roadmap.md`:
```
| NN | <дата> | picoctf | <категория> | [[ctf/picoctf/<cat>/<task>\|<task>]] | <главное> |
```
Одна строка на **решённый** таск (не на сессию). Нерешённые в журнал не добавлять.

## Структура vault для CTF

```
knowledge-base/
└── ctf/
    └── picoctf/
        ├── session-01.md          # журнал сессии
        ├── web/
        │   └── <task-name>.md     # writeup
        ├── general-skills/
        └── crypto/
```

Reverse/pwn-папок не заводим — эти категории не в фокусе.

---

## Связь с OWASP Top 10

Web-челленджи привязывать к OWASP-категории в writeup (поле `owasp:`).
Когда наберётся 5–6 web-writeup'ов — свести в `topics/security/owasp-top10.md`
(карта: какая категория, какой челлендж её иллюстрирует). Это и есть подготовка к собесу.

---

## Чего не делать

- Не предлагать Reverse/Pwn/тяжёлую крипту/stego — не вектор AppSec.
- Не давать готовый payload как hint — направление, не решение.
- Не пропускать writeup для нетривиальных тасков — flag без writeup = впустую.
- Не забывать привязку к `topics/security/` и OWASP-категории.
- Не делать сессии длиннее 90 минут — это параллельный трек.
- Не предлагать CTF из `give-task` — пользователь сам решает темп.
