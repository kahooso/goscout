# Скилл: session-debrief

Триггеры:
- пользователь пишет «на этом всё» / «заканчиваем»
- пользователь правильно ответил на 2–3 уточняющих вопроса из `explain-code` подряд
  без путаницы → предложить: «Кажется разобрались. Закончим сессию?» —
  дождаться подтверждения.

Сигнал: сессия завершена, нужно зафиксировать результаты.

---

## Алгоритм

### Шаг 1 — Задать один вопрос

«Что вызвало затруднение в этой сессии — <тема1> или <тема2>?» (или открытый вариант).
Один вопрос. Кратко. Ждать ответа.

### Шаг 2 — Зафиксировать в vault

Вызвать `vault-write`. Передать ответ из Шага 1 — повторно не спрашивать.

Что обновить:
- **task-файл рядом с кодом** — `sections/<домен>/<имя>/task-<блок><NN>-<имя>.md`:
  разделы «Моё решение», «Что узнал», «Ошибки и трудности», «Что бы сделал иначе».
  Код задания живёт в ДРУГОМ репозитории (outpost) → файл в `knowledge-base/tasks/`
- `knowledge-base/topics/go/<тема>.md` — раздел «Личный опыт» (новый формат)
- Если в коде остались длинные `// A:` — перенести в topics/, в коде оставить ссылку

### Шаг 3 — Обновить файлы прогресса

> Четыре файла с непересекающимися ролями — писать строго по назначению.
> Роли: `roadmap/00-roadmap.md` (где я сейчас), `roadmap/journal.md` (что сделано),
> `roadmap/archive.md` (закрытые блоки), `strategy/learning-strategy.md` (только будущее).

**`knowledge-base/roadmap/journal.md`** (только журнал):
- Добавить строку: номер, блок, название, статус, дата

**`knowledge-base/roadmap/00-roadmap.md`** → «Текущая позиция»:
- Обновить «Последний task» + дату
- При ЗАКРЫТИИ блока — дамп освоенных тем переносится в `roadmap/archive.md`
- Обновить «Следующая задача» (по плану блока)
- Увеличить счётчик задач с последнего мок-собеса на 1
- Обновить «Слабые места», если сессия что-то выявила

**`knowledge-base/strategy/learning-strategy.md`** — только если менялся ПЛАН:
- Выполненное задание **вычёркивается** из карты блока (файл держит будущее, не прошлое)

**`sections/leetcode/00-roadmap.md`** — для алго-задачи: отметка `[x]` + «Слабые паттерны».

### Шаг 4 — Обновить CLAUDE.md (если требуется)

**Обязательно** обновить если:
- Создана новая папка `sections/<домен>/<имя>/` → дописать в раздел «Структура проекта»
- Изменился стек / уровень → обновить или добавить ссылку в memory
- Освоена новая категория тем (сети, security)

Если ничего из этого — CLAUDE.md не трогать.

### Шаг 5 — Обновить скиллы

Если в сессии пользователь корректировал поведение Claude («не так», «лучше так», «почему ты не…»):
- Найти соответствующий `skill.md`
- Дописать правило, чтобы такая корректировка не понадобилась в будущем
- Цель: каждый следующий запуск — без повторных подсказок

### Шаг 6 — Обновить memory (если применимо)

Сохранить в memory если:
- Выявилась **повторяющаяся** ошибка (паттерн, не разовое)
- Новое предпочтение по стилю/процессу
- Изменился уровень знаний (`user_go_level.md`)

Не сохранять разовые факты — для них есть `tasks/`.

### Шаг 7 — Чеклист синхронизации

Прежде чем сказать «готово»:

- [ ] task-файл создан или обновлён (рядом с кодом в `sections/`, либо в `tasks/` для outpost)
- [ ] `roadmap/journal.md` содержит новую строку (для CTF — строка в разделе `## CTF`)
- [ ] `roadmap/00-roadmap.md` → «Текущая позиция» обновлена (последний task, темы, счётчик)
- [ ] Новые/изменённые `topics/` в новом формате (TL;DR + ссылка + личный опыт + English-глоссарий)
- [ ] `topics/_index.md` обновлён если появился новый topic
- [ ] CLAUDE.md → структура `sections/` актуальна (если создан новый `sections/<домен>/<имя>/`)
- [ ] Длинные `// A:` из кода перенесены в `topics/`
- [ ] Memory обновлена при повторяющемся паттерне / новом предпочтении

Если пункт пропущен — закрыть его прежде чем сказать «готово».

---

## Чего не делать

- Не пропускать Шаг 1 — ответ важен для честной фиксации трудностей.
- Не писать «всё прошло отлично» если были провалы. Провалы фиксировать как провалы.
- Не обновлять CLAUDE.md если структура проекта не менялась — иначе шум в diff.
- Не запускать дебриф если пользователь просто читает CLAUDE.md, не в конце сессии.
