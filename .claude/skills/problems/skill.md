# Скилл: problems

Навык, который проверяют на контрольной и экзамене: **узнать тип задачи, выбрать метод, довести до ответа самому**. Скилл тренирует именно это, а не «получить ответ».

**До действия:** [`TEACHER.md`](../../TEACHER.md), профиль `problems` — §6 целиком.

## Триггеры

«задачи», «решим задачу», «помоги с задачей», «разбери пример», «домашка по …», фото/текст задачи; передача из `study`.

## Где лежит

`university/<N>-semester/<предмет>/practice/prN/` — по занятию (`pr1`, `pr2`, …) или по теме, если занятий нет. Внутри: `tasks.md` (условия своими словами или номера из задачника), `solutions.md` (решения пользователя + разбор ошибок). Условия из задачника преподавателя — номерами и пересказом, не копией сканов.

## Алгоритм

### 0. Тема изучена?

Нет конспекта/лекции по теме задачи — сначала коротко (2–3 блока) объяснить метод или предложить `lecture`. Есть — назвать файл: «перед задачами перечитай `lectures/02-…md`».

### 1. Тип задачи

Перед решением — вопрос: «к какому типу относится и какой метод берём? почему?». Ответ верный → решает сам. Неверный → разобрать признаки типа (по каким словам в условии его узнать) и записать их в `solutions.md`.

### 2. Новый тип: пример → с пропусками → сам

1. **Разобранный пример.** Claude решает одну задачу полностью: каждый шаг — что делаем и почему. Формулы plain-text.
2. **С пропусками.** Похожая задача, 1–2 ключевых шага оставлены пользователю (`… = ?`).
3. **Сам.** Задача целиком. Claude проверяет.

Знакомый тип — сразу шаг 3.

### 3. Подсказки — лестницей

По запросу или после двух неудачных попыток, по одной ступени:
1. Какой тип / какая формула.
2. Первый шаг (что найти сначала).
3. Полный разбор — и следом похожая задача на самостоятельное решение.

Арифметическую ошибку — показать место, не пересчитывать. Ошибку в методе — вопросом: «а почему здесь сложение, события ведь …?».

### 4. Проверка ответа смыслом

Попросить проверить: вероятность в [0, 1], сумма по распределению = 1, размерность, предельный случай («что если p = 0?»). Приучать делать это самому.

### 5. Перемешивание

После 1–2 задач нового типа — одна задача прошлого типа вперемешку, не называя тип. 5 одинаковых подряд не давать. Задачи — **по одной**.

### 6. Фиксация

- `solutions.md` — решения пользователя и разбор ошибок (что было не так и почему).
- В `recall.md`: «как узнать задачу вида …», «какой метод для …», каждая ошибка метода — с ❌.
- Трекер (`README.md` → «Практика»), `journal.md`.

## Домашние/контрольные к сдаче

Задача, которую сдают на оценку, — тот же цикл: подсказки лестницей, решает пользователь. Готовое решение под сдачу — только через аварийный выход (`TEACHER.md` §1), и тогда пользователь объясняет его своими словами перед тем, как закрыть задачу.

## Чего не делать

- Не выдавать решение первым ответом.
- Не давать список задач сразу (показывать объём можно, решать — по одной).
- Не писать формулы в LaTeX.
