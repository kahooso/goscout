# Скилл: defense

Защита — узкое место: отчёты сдаются, а на устном «ноль» (ЛР-5 схемотехники: 2/5). Скилл готовит к **устному воспроизведению**, а не к узнаванию.

**До действия:** [`TEACHER.md`](../../TEACHER.md), профиль `defense` (§4, §5, §8).

## Триггеры

«защита», «к защите», «допуск», «зачёт», «экзамен», «прогони меня», передача из `study` / `lab`.

## Алгоритм

### 1. Контекст

- Трекер предмета: дата защиты/экзамена, что входит.
- `private.md` предмета: как спрашивает этот преподаватель (прошлые защиты: какие вопросы, что просил показать).
- Отчёт (`.docx` — только читать) и `zashchita.md`, если есть; контрольные вопросы методички; `recall.md`.

Одна строка: «Защита ЛР-N <дата>. Время: <сколько осталось>. План: …».

### 2. План по времени

| Осталось | Что делаем |
|---|---|
| > 3 дней | полный разбор по отчёту (шаг 3) → `zashchita.md` → пробная защита за день до |
| 1–2 дня | разбор только ключевых частей отчёта + пробная защита |
| < 1 дня | сразу пробная защита, по провалам — короткий доразбор, шпаргалка «5 главных фраз» |

Показать план, ждать «погнали».

### 3. Разбор по отчёту

Идём по отчёту по порядку. Для каждой части:
1. Если для её объяснения нужна теория, которой ещё не было, — сначала теория (простым языком, на числах из отчёта).
2. Пользователь своими словами объясняет эту часть: что делали, что получилось, почему так.
3. Claude правит по сути, коротко.
4. Удачная формулировка пользователя → в `zashchita.md` (его словами, Claude только поправляет неточности).

Один раздел отчёта = один блок (гейтинг).

### 4. `zashchita.md`

Структура: цель работы в 1–2 предложения → схема/установка: что из чего и зачем → ключевые результаты с числами и объяснением → контрольные вопросы методички с ответами → вероятные вопросы преподавателя → **[показать]** — что могут попросить открыть/показать и где это. Язык — тот, которым пользователь будет говорить.

### 5. Пробная защита

Claude играет преподавателя (стиль — из `private.md`; нет данных — строгий, спрашивает «почему» и просит показать).
- Вопросы **по одному**, без подсказок. Перед ответом — уверенность 1–5 (TEACHER.md §4).
- Смесь: 1/3 — «что делали и что получилось», 1/3 — «почему так» / «что будет, если», 1/3 — практические («покажи на графике, где частота среза», «открой схему, что это за элемент»).
- Ответ не разбирать сразу — после 5–7 вопросов дать итог: где уверенно, где поплыл, где ошибка при высокой уверенности.
- Провалы → короткий доразбор → вопросы в `recall.md` с ❌ → повтор этих вопросов **не сегодня**, а в следующую сессию (или утром перед защитой).

### 6. Экзамен/зачёт по всему курсу

Шафл-тест по `recall.md` всех тем (10–15 вопросов вперемешку) → список слабых тем → по каждой `lecture` (сокращённо) или `problems` → повторный шафл через 1–2 дня.

### 7. После защиты

Спросить: что спрашивали, где поплыл, итог. Записать: трекер (статус, оценка), `journal.md`, стиль преподавателя — в `private.md`, проваленные вопросы — в `recall.md`.

## Чего не делать

- Не писать `zashchita.md` целиком за пользователя — формулировки его, Claude правит.
- Не подсказывать во время пробной защиты.
- Не переигрывать проваленные вопросы в тот же час — это проверяет кратковременную память.
- Не изменять `.docx` отчёта.
