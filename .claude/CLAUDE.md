# CLAUDE.md — Мастер-инструкция

Этот файл загружается автоматически при каждом запуске Claude Code.
Определяет роль и поведение Claude. Должен быть **коротким** — детали в memory и скиллах.

## Старт новой сессии — обязательно сделать первым делом

Перед тем как реагировать на первое сообщение пользователя:

1. Прочитать `.claude/strategy/learning-strategy.md` → раздел «Текущая позиция»
   (последний task, освоенные темы, счётчик мок-собеса, следующая задача).
2. Проверить memory (`user_go_level.md`, `feedback_llm_dependency.md` — главные).
3. В первом ответе **одной строкой** подтвердить контекст:
   «Контекст: A0.X, последний task-NN, следующая — <тема>. Готов.»
   Это даёт пользователю уверенность что Claude не забыл состояние.

Только после этого — реагировать на запрос пользователя по таблице скиллов ниже.

## Реестр скиллов — ОБЯЗАТЕЛЬНО читать перед действием

Claude обязан прочитать соответствующий `skill.md` **до** того как действовать.

| Триггер | Скилл |
|---------|-------|
| «объясни код / концепцию / протокол» | `skills/explain-code/skill.md` |
| «ревью» / показываю код | `skills/code-review/skill.md` |
| «у меня есть N часов» / «дай задание» | `skills/give-task/skill.md` |
| «не компилируется» / «паника» / «не работает» | `skills/debug/skill.md` |
| «добавь в vault» / вызов из другого скилла | `skills/vault-write/skill.md` |
| «мок-собес» / счётчик ≥ 8 в стратегии | `skills/mock-interview/skill.md` |
| «на этом всё» / тема усвоена | `skills/session-debrief/skill.md` |

**Тема не из стратегии**: не отказывать. Выяснить зачем. Если вписывается в вектор —
добавить в `learning-strategy.md`, дальше работать как обычно.

**Обновление скиллов**: если пользователь корректирует поведение («не так», «лучше так») —
обновить соответствующий `skill.md`. Скиллы должны улучшаться от сессии к сессии.
