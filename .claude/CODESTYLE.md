# CODESTYLE.md — конвенции кода на Go

Эталон для сверки. Читается **перед тем как писать код** и **перед ревью**.
Расхождения выносятся в ревью **отдельной секцией** — не смешиваясь с багами:
стиль приводится к единому виду сознательно, чтобы не тратить проектирование на то,
что уже решено.

Объяснения «почему так» здесь не дублируются — ссылка на конспект в `knowledge-base/topics/go/`.

---

## 1. Форматирование — не обсуждается

`gofmt` канонический и единственный. Табы, переносы, выравнивание — его работа.
Спорить не о чем, ставить `gofmt -w` в ритуал перед коммитом.
→ [go-tooling.md](../knowledge-base/topics/go/go-tooling.md)

## 2. Имена

- `MixedCaps`, не `snake_case`. Экспорт — с заглавной, остальное со строчной.
- **Длина имени обратна размеру области видимости.** `i`, `n`, `b` в трёх строках цикла —
  нормально; `resolvedTargetAddress` там же — шум. Пакетная переменная — полное имя.
- Интерфейс на один метод — по имени метода с `-er`: `Resolver`, `Dialer`, `Prober`.
- Не повторять имя пакета в имени функции: `net.DialTimeout`, не `net.NetDialTimeout`.
- Ошибки-значения — `ErrXxx` (`ErrNotFound`), типы ошибок — `XxxError`.
- Тесты: `TestФункция_случай`, подтест `t.Run("пустой ввод", ...)`.

## 3. Раскладка по файлам

Один файл = одна ответственность, имя файла = что внутри. Раскладка сделана в task-12
и работает: `probe.go` (общий контракт и раннер), `dns.go`, `ports.go` (реализации),
`input.go` (чтение и парсинг ввода), `main.go` (только разбор аргументов и вызов).

- `main.go` не содержит логики — только сборку и запуск.
- Тесты рядом: `ports.go` → `ports_test.go`.
- Файл перевалил за ~250 строк — повод разложить, а не «дописать ещё функцию».

## 4. Контракты функций

- **`context.Context` — всегда первый параметр**, имя `ctx`. Не хранить в структуре.
- **`error` — всегда последний возврат.** Не смешивать с bool-флагами успеха.
- Зависимость, которую нужно подменить в тесте (сеть, часы, файлы), принимается
  **через маленький интерфейс**, объявленный потребителем, с фолбэком на реальную
  реализацию при нулевом значении. Образец — `Resolver`/`Dialer` в outpost.
  → [interfaces.md](../knowledge-base/topics/go/interfaces.md)
- Функция, которая печатает, принимает `io.Writer`, а не пишет в `os.Stdout` напрямую —
  иначе вывод нельзя проверить тестом.

## 5. Обработка ошибок

- Каждая `err` проверяется. Игнорирование — только явное `_ =` с комментарием почему.
- **Контекст добавляется через `%w`, а не через имя функции:**
  `fmt.Errorf("invalid port %q: %w", raw, err)`. `%w` сохраняет цепочку для
  `errors.Is`/`errors.As`; имя функции читателю не помогает.
  → [errors.md](../knowledge-base/topics/go/errors.md)
- Не логировать и возвращать одновременно — один раз, на верхнем уровне.
- Паника — только на неисправимом состоянии программы, не на плохом вводе.

## 6. Вывод CLI

- **stdout = данные, stderr = ошибки и диагностика.** Их разделяют при запуске
  (`> file`, `2>/dev/null`), смешивание ломает конвейеры.
- Коды выхода: `0` успех, `1` ошибка выполнения, `2` ошибка аргументов.
  Человек читает stderr, скрипт читает код выхода.
- Для CLI — `fmt.Fprintf`, без `log`/`slog`: структурные логи нужны сервису, не утилите.
  → [stdlib-cli.md](../knowledge-base/topics/go/stdlib-cli.md)

## 7. Тесты

- Table-driven + `t.Run` на каждый случай. Минимум три: обычный, граничный, злой.
- **Перед каждым `if` в тесте ответить: какая поломка кода покрасит эту проверку.**
  Нет ответа — проверка тавтологическая.
- **Мутацию прогонять руками**: сломать код, убедиться, что тест покраснел, вернуть.
  Не принимать на слово.
- Заглушка обязана соблюдать контракт зависимости, которую подменяет.
- Concurrency — только с `-race`.
  → [testing.md](../knowledge-base/topics/go/testing.md)

## 8. Конкурентность

- У каждой горутины виден выход. Нет ответа «когда она завершится» — это утечка.
- Канал закрывает **отправитель**, и только он.
- Буфер канала выбирается осознанно: `len(items)` для сборщика — чтобы отправители
  не блокировались, когда получатель ушёл по таймауту.
- Отмена — через `context`, проверка `ctx.Err()` там, где результат уже неактуален.
  → [channels.md](../knowledge-base/topics/go/channels.md), [context.md](../knowledge-base/topics/go/context.md)

## 9. Чего избегать — переносы из C/C++

Повторяющиеся привычки, помечать пока не уйдут (memory `feedback_c_idioms_in_go`):

- лишние nil-проверки в бизнес-логике «на всякий случай»;
- `var x []T = ...` там, где хватает `:=`;
- явная инициализация нулевых значений (`IsDone: false`, `Count: 0`);
- `make(map[K]V, 0)` вместо `map[K]V{}`;
- геттеры/сеттеры на каждое поле без причины.

## 10. Ритуал перед коммитом

```
gofmt -w ./...
go vet ./...
go test -race ./...
go build ./...
```

Ровно это гоняет CI. Красный CI на публичном репозитории видят все.
