# Как пользоваться этим проектом

Шпаргалка для пользователя.

---

## Дефолтный workflow

**Стандартная сессия выглядит так:**

1. Открываешь Claude Code в проекте.
2. Копи-пастишь стартовое сообщение (см. ниже) — Claude поднимает контекст.
3. Пишешь: **«у меня есть N часов, дай задание»** — и всё.
4. Claude сам:
   - читает где ты сейчас в плане
   - проверяет не нужен ли мок-собес
   - спрашивает уверен ли ты в предыдущей теме
   - проводит 3 фазы (концепция → пакет → контрольные вопросы)
   - выдаёт задание
   - проводит ревью кода
   - обновляет vault + стратегию
5. В конце пишешь **«на этом всё»** — Claude фиксирует сессию.

Тебе **не нужно** знать «какая следующая тема», «какой скилл вызвать», «что записать в vault».
Это **работа Claude**. Ты — пишешь код, отвечаешь на вопросы, говоришь когда непонятно.

---

## Стартовое сообщение (копи-паст в новой сессии)

```
Подними контекст: прочитай .claude/CLAUDE.md, knowledge-base/roadmap/00-roadmap.md
и memory проекта — все файлы.

Ответь СТРОГО в формате:
- блок: <идентификатор>
- последний task: <NN, тема>
- следующая задача: <тема или мок-собес>
- проверил memory: да/нет — какие файлы прочитал

После этого жди мой запрос.
```

**Если ответил не в формате** — это признак что Claude схалтурил.
Скажи: «Ответь СТРОГО в формате выше».

**Если в строке "проверил memory" не упомянуты как минимум `project_vector_backend_go.md`,
`user_go_level.md`, `feedback_think_independently.md`** — память не подгружена.
Скажи: «Перечитай memory полностью, особенно `project_vector_backend_go.md`».

## Аварийный выход (если задача невозможная)

Если задача оказалась слишком сложной — **не мучай себя**. Скажи Claude:
- «Сдаюсь, покажи решение»
- «Я застрял, дай разбор»
- «Ничего не понимаю в этой задаче»

Claude должен **без пристыжения** показать решение и пошагово объяснить.
Это записано в memory `feedback_think_independently.md` → раздел «Аварийный выход».

После этого ты **не теряешь прогресс** — задача засчитывается, в `tasks/task-NN.md`
фиксируется «застрял на X, разобрали вместе». Следующая задача — на том же уровне,
не на сниженном.

## Главная фраза дня

После подтверждения контекста, в 90% случаев пишешь:

> **«У меня есть N часов, дай задание»**

или просто **«дай задание»** / **«поехали»**.

Claude запустит скилл `give-task` и проведёт тебя через всё. От тебя — отвечать на вопросы и писать код.

## Когда писать что-то другое (опционально)

| Хочу нечто специфичное | Что писать |
|------------------------|------------|
| Сейчас разобрать тему/код/протокол (не задание, а понять) | «Объясни X» |
| Показать код на ревью отдельно от задания | «Проверь» + код |
| Помощь при ошибке/панике | «Не компилируется» / «паника» + текст ошибки |
| Мок-собес по пройденному вне очереди | «Проверь меня» / «мок-собес» |
| **Алго-задача для размятия** | «Дай алго-задачку» / «давай алгоритм» / «LeetCode» |
| **Разобрать теорию по УЖЕ написанному коду** (код работает, а почему — не уверен) | «Разбери мой код по теории» |
| **Почитать чужой код** (stdlib) вместо написания своего | «Дай почитать код» / «как это сделано в stdlib» |
| **Спроектировать новый блок** (активного блока нет) | «Спроектируй блок» — Claude разложит карту заданий |
| Тема не из плана, но хочу разобрать | «Хочу разобраться в X» — Claude уточнит зачем и впишет в стратегию |
| Конец сессии (зафиксировать всё) | «На этом всё» / «заканчиваем» |

В остальных случаях — дефолтная фраза выше.

### Про алго-задачи специально

Алго-задачи (Two Sum, Contains Duplicate, etc) — это **параллельная ветка**,
не замена основного плана. Используй когда:
- Хочешь закрепить базу (slices/maps/pointers) на чистом мышлении
- После задачи A0 осталось 30–60 минут и брать новую тему рано
- Хочешь тренировать собеседовательный формат

План и прогресс трека — [`sections/leetcode/00-roadmap.md`](../sections/leetcode/00-roadmap.md).
Прогресс определяет отметка `[x]`, а не наличие папки: папка заводится при выдаче задания.
Claude даёт **список из 2–4 задач** — выбираешь сам, что и сколько решать.

Не делай марафон по LeetCode. ~1 algo-задача на 2–3 task блока A0 — норма.

## Как задавать вопросы во время кода

Когда пишешь решение задачи и появляется вопрос — **не уходи в чат**.
Оставь в коде:

```go
// ? Почему здесь pointer receiver, а не value?
func (s *Stack) Push(v int) {
    // ...
}
```

Когда покажешь код на ревью — Claude ответит на все `// ?` прямо в коде,
заменив на `// A: <ответ>`. История твоего мышления остаётся в файле.

---

## Конец сессии

Когда задача сдана и ревью прошло — пиши **«на этом всё»** / **«заканчиваем»**.
Это запускает `session-debrief`:
- спросит что было сложным (1 вопрос)
- обновит `tasks/task-NN.md`, `topics/<тема>.md`
- обновит roadmap, стратегию, счётчик мок-собеса
- обновит CLAUDE.md если появилась новая папка `sections/<домен>/<имя>/`

**Без этой фразы** часть знания может остаться незафиксированной.

---

## Если Claude ведёт себя не так

Скажи как именно — он обновит соответствующий `skill.md` или memory.
Примеры:
- «Ты сразу выдал решение — должен был подсказку. Обнови скилл.»
- «Ты не упомянул видео Тузова на новой теме. Это правило в memory.»
- «Ты пропустил Фазу 1 — это нарушение `give-task`.»

**Не молчи** про корректировки — это улучшает Claude от сессии к сессии.

---

## Признаки что сессия «уплыла»

- Claude предлагает темы вне `learning-strategy.md`
- Забыл про мок-собес перед A0.6, начал давать A0.6
- Игнорирует `// ?` вопросы в коде
- Слишком быстро даёт готовый код вместо подсказок (нарушает memory `feedback_think_independently`)
- Пишет «отличный вопрос!» (запрещено)
- Длинные `// A:` комментарии в коде вместо переноса в vault

Реакция: «Стоп. Подними контекст: текущая позиция, что должно быть следующим.»
Или просто закончи сессию (`на этом всё`) и начни новую со стартовым сообщением.
