# ЛР-1 — конспект к защите: оптимизирующие компиляторы + ассемблер

Простым языком, с нуля. Повторить перед защитой.
Сделано на GCC 15.2.0, ассемблер в синтаксисе **Intel** (`-masm=intel`).

## Часть 1. Как читать ассемблер (основы)

**Ассемблер** — это команды, которые понимает сам процессор. Они крошечные: «возьми число»,
«сложи», «сравни», «прыгни». Компилятор переводит код на Си в такие команды.

Две главные вещи, которые надо различать:
- **Память** — это переменные программы. Запись `i2[rip]` = «переменная `i2`».
- **Регистры** (`eax`, `rax`, `edx`…) — это крошечные ячейки **внутри процессора**, его черновик.
  Процессор не умеет копировать из памяти прямо в память — сначала тащит число в регистр,
  потом из регистра в нужную переменную.

**Шпаргалка по обозначениям:**

| Запись | Что значит |
|---|---|
| `i2[rip]` | переменная `i2` (глобальная, в памяти). `[rip]` — стандартный способ дотянуться до глобалки |
| `DWORD PTR` | «размером 4 байта» = обычный `int`. `QWORD` = 8 байт, `WORD` = 2, `BYTE` = 1. **`PTR` — это НЕ указатель**, а пометка размера |
| `[rax]` | значение по адресу, который лежит в регистре `rax` (вот тут `rax` работает как настоящий указатель) |
| `[rdx+rax]`, `[rcx+rax*8]` | адрес, собранный из частей: база + индекс (× масштаб) |
| `; текст` | комментарий (процессор его не видит) |
| `.L2:` | метка — закладка в коде, куда можно прыгнуть |

Команды читаются **справа налево**: `mov A, B` = «B положить в A».

## Часть 2. Регистры: сколько их и какие

### 64-битный режим (x86-64) — 16 регистров общего назначения

```
rax  rbx  rcx  rdx  rsi  rdi  rbp  rsp
r8   r9   r10  r11  r12  r13  r14  r15
```
Каждый — 64 бита (8 байт).

### 32-битный режим (x86) — 8 регистров общего назначения

```
eax  ebx  ecx  edx  esi  edi  ebp  esp
```
Каждый — 32 бита (4 байта). (Регистров `r8…r15` в 32-битном режиме нет — они появились только в 64-битном.)

### Как связаны разные размеры (на примере rax)

Это **один и тот же** физический регистр, просто обращаемся к разному куску:

| Имя | Размер | Что это |
|---|---|---|
| `rax` | 64 бита (8 байт) | весь регистр |
| `eax` | 32 бита (4 байта) | младшая половина `rax` |
| `ax` | 16 бит (2 байта) | младшая часть `eax` |
| `al` | 8 бит (1 байт) | самый младший байт |

То же для остальных: `rbx`→`ebx`→`bx`→`bl`, а у новых — `r8`→`r8d`→`r8w`→`r8b`.

### Специальные регистры (не «общего назначения»)

- **`rip`** (в 32 бит — `eip`) — указатель на **текущую команду**. Отсюда `i2[rip]`.
- **`rflags`** (`eflags`) — регистр **флагов** (результаты сравнений, см. Часть 4).
- **`rsp`** — указатель вершины **стека**, **`rbp`** — база стекового кадра функции.
- **`xmm0…xmm15`** — отдельные регистры для **дробных** чисел (float/double). В коде это `movsd`, `xmm0`.
- Сегментные (`cs`, `ds`, `ss`, `es`, `fs`, `gs`) — в обычном коде почти не трогаем.

**Короткий ответ на вопрос «сколько регистров»:** общего назначения — **8 в 32-битном** режиме
и **16 в 64-битном**. Плюс указатель команд, регистр флагов и набор `xmm` для дробных чисел.

## Часть 3. Основные инструкции (справочник)

| Команда | Что делает | Пример |
|---|---|---|
| `mov A, B` | скопировать B в A (B не меняется) | `mov eax, 5` → eax=5 |
| `lea A, [...]` | вычислить **адрес** выражения в скобках и положить в A (не значение!) | `lea rax, ivector[rip]` → адрес массива |
| `add A, B` / `sub A, B` | A = A + B / A = A − B | `add eax, 1` |
| `inc A` / `dec A` | A = A + 1 / A = A − 1 | `inc rax` |
| `imul` / `mul` | умножение (знаковое / беззнаковое) | `imul eax, ecx` |
| `idiv` / `div` | деление | `idiv r8d` |
| `sal`/`shl A, n` | сдвиг **влево** на n = умножить на 2ⁿ | `sal eax, 2` = ×4 |
| `sar`/`shr A, n` | сдвиг **вправо** на n = разделить на 2ⁿ | `sar eax, 1` = ÷2 |
| `xor A, B` | побитовое ИЛИ-исключающее. `xor eax, eax` → eax=0 (быстрый способ обнулить) | `xor eax, eax` |
| `cmp A, B` | сравнить A и B (выставляет флаги, результат не хранит) | `cmp eax, 2` |
| `test A, B` | побитовое И, тоже для проверки (часто `test eax, eax` — проверка на 0) | `test eax, eax` |
| `jmp .L` | прыгнуть на метку **безусловно** | `jmp .L2` |
| `je/jne` | прыгнуть если равно / не равно | см. Часть 4 |
| `jl/jle/jg/jge` | прыгнуть если меньше / ≤ / больше / ≥ (знаковые) | см. Часть 4 |
| `call f` / `ret` | вызвать функцию / вернуться из неё | `call printf` |
| `push`/`pop` | положить/снять со стека | `push rbx` |
| `movsd` | `mov` для дробных чисел (double) | `movsd xmm0, ...` |
| `cdqe`/`cdq` | расширить число до большего размера (служебное) | — |
| `nop` | ничего не делать | — |

### Про `lea` (спрашивают особенно часто)

`lea` = **load effective address** = «вычисли, ГДЕ оно лежит, и положи этот адрес».
Отличие от `mov`: `mov` достаёт **значение**, `lea` — только **адрес** (где лежит), в память не лезет.

Два применения:
1. **Взять адрес:** `lea rax, ivector[rip]` → в rax адрес массива (чтобы потом ходить по нему).
2. **Арифметика-трюк:** скобки умеют «база + индекс×масштаб + число», и это считают за одну
   дешёвую команду. Поэтому `lea` используют вместо умножения:
   - `lea eax, [rax+rax]` → `eax = rax×2`
   - `lea eax, [rax+rax*4]` → `eax = rax×5`
   - `lea eax, [rdi+rdi*2]` → `eax = rdi×3`

### Про `mov`

`mov` (от *move*) — на деле **копирование**. `mov A, B` кладёт значение B в A, B остаётся.
В одной команде **только одна** ячейка памяти: нельзя `mov [память], [память]` — нужен регистр-посредник.

## Часть 4. Связка `cmp` + `jl/jg` и флаги

Это основа всех `if` и циклов. Работает в два шага.

**Шаг 1 — `cmp A, B`.** Процессор мысленно считает `A − B`, но результат **не сохраняет** —
он лишь выставляет **флаги** в регистре флагов (`rflags`):
- **ZF** (zero flag) = 1, если A = B (разность нулевая);
- **SF** (sign flag) = знак результата (минус или плюс);
- **OF** (overflow) — было ли переполнение;
- **CF** (carry) — перенос (для беззнаковых сравнений).

**Шаг 2 — условный переход** читает эти флаги и решает, прыгать или нет:

| Переход | Прыгнет, если | По флагам |
|---|---|---|
| `je` | A = B | ZF = 1 |
| `jne` | A ≠ B | ZF = 0 |
| `jl` | A < B (знаковое) | SF ≠ OF |
| `jle` | A ≤ B | ZF = 1 или SF ≠ OF |
| `jg` | A > B | ZF = 0 и SF = OF |
| `jge` | A ≥ B | SF = OF |
| `jb`/`ja` | < / > для **беззнаковых** | по CF/ZF |

**Пример:**
```asm
cmp  eax, 2
jle  .L3        ; если eax <= 2, прыгнуть на .L3
```
Это ровно `if (eax <= 2) goto .L3;`.

Итог: **`cmp` сравнивает и записывает результат во флаги, а `jl`/`jg`/… читают флаги и решают,
прыгать или нет.** Разделение: одно сравнение — можно потом по нему сделать разные переходы.

## Часть 5. Регистр vs память — почему регистр лучше

- **Регистр — внутри процессора**, доступ почти мгновенный.
- **Память (ОЗУ) — снаружи**, сходить туда за числом в разы дольше (даже с кэшами — медленнее регистра).
- Большинство команд умеют работать прямо с регистрами; с памятью — с ограничениями
  (нельзя два обращения к памяти в одной команде).

Аналогия (это и есть суть): **регистры — то, что лежит у тебя на столе** (берёшь мгновенно);
**память — шкаф с документами в другом конце комнаты** (надо встать и сходить).

Поэтому компилятор старается **держать часто используемые значения в регистрах** и писать
обратно в память только когда надо — чем меньше походов в память, тем быстрее программа.
Минус: регистров мало (8 или 16), всё не влезает — лишнее «выгружается» (spill) обратно в память.

Это прямо видно в `-O0` vs `-O2`: на `-O0` компилятор после каждого шага пишет значение обратно
в память и потом снова грузит; на `-O2` держит его в регистре и в память лишний раз не ходит.

## Часть 6. Что делает компилятор в каждом из 17 блоков

Для каждого: код на Си → что в `-O0` → что в `-O2`/`-Os` → суть.
(Полные листинги — в `otchet.md` и в `таблицы.docx`.)

### 1. Отказ от циклов
`for(i=0;i<3;i++) ivector[i]=1;` — короткий цикл заполнения.
Было (`-O0`): настоящий цикл ~15 команд. Стало (`-O2`/`-Os`): цикл убран, 3 прямые записи
(две соседние ячейки — одной 8-байтной командой). **Суть:** короткий предсказуемый цикл
развёрнут в прямые присваивания.

### 2. Переприсваивание
`i2=5; j4=6; i2=j4;`
Было: 4 команды. Стало: `mov i2, 6` — одна. **Суть:** `i2=5` — мёртвое (сразу перезаписано),
убрано; `j4=6` — константа, поэтому `i2=j4` → `i2=6` напрямую.

### 3. Размножение констант и копий
`j4=2; if(i2<j4&&i4<j4){...} j4=k5; if(...){...}`
Было: каждое сравнение грузит `i2`/`j4` из памяти. Стало: `i2=6` подставлено в сравнение
(`cmp eax,6`), первый `if` вычислен при компиляции (`6<2` ложно) и удалён вместе с `printf`.
**Суть:** известные значения подставляются прямо в команды, мёртвые ветки удаляются.

### 4. Свёртка констант, тождества, лишние load/store
`i3=1+2; flt_1=2.4+6.3; j2=i+0; k2=i/1; i4=i*1; i5=i*0;`
`1+2`→`3`, `2.4+6.3`→`8.7` посчитаны при компиляции; `i+0`→`i`, `i/1`→`i`, `i*1`→`i`,
`i*0`→`0`. **ВАЖНО: всё это делается даже на `-O0`** — настолько базовые приёмы, что идут всегда.

### 5. Лишнее присваивание
`k3=1; k3=1;` → одна запись. **Суть:** вторая запись того же значения бессмысленна (мёртвая), убрана.

### 6. Снижение мощности
`k2=4*j5; for(i=0;i<=5;i++) ivector4[i]=i*2;`
`4*j5` → сдвиг `sal eax,2` (умножение заменено дешёвым сдвигом) — уже на `-O0`.
Цикл `i*2` на `-O2`/`-Os` развёрнут и посчитан заранее (`0,2,4,6,8,10`).
**Суть:** дорогая операция → дешёвая (умножение → сдвиг).

### 7. Простой цикл
`do{k5--; j5++; i5=(k5*3)/(j5*5);}while(k5>0);` (10000 проходов).
Стало: `j5=10000; i5=0;` — **весь цикл посчитан при компиляции** и исчез. **Суть:** результат
цикла вычислим заранее → цикла нет.

### 8. Управление переменной индукции цикла
`for(i=0;i<100;i++) ivector5[i*2+3]=5;`
Цикл остаётся (пишет 100 ячеек — реальная работа), но вместо пересчёта адреса `i*2+3` каждый
раз заведён **указатель**, шагающий на фиксированные 8/16 байт. `-O2` разворачивает ×2, `-Os` — нет.
**Суть:** умножение из цикла заменено «шагающим указателем». (Отсюда предупреждение про `ivector5`.)

### 9. Глубокие подвыражения
`if(i<10) j5=i5+i2; else k5=i5+i2;`
Стало: `k5=5`. **Суть:** `i=100` известно → ветка `else`, подвыражение `i5+i2=0+5=5` посчитано.

### 10. Константный адрес, копии и регистры
`ivector[0]=1; ivector[i2]=2; ivector[i2]=2; ivector[2]=3;`
`[0]` и `[2]` — адрес известен сразу (числовой индекс). `i2=5` известно → `ivector[i2]` = прямое
смещение `+20`. Две одинаковые записи `ivector[i2]=2` → одна. **Суть:** известный индекс → прямой
адрес; повтор убран.

### 11. Удаление общих подвыражений (CSE)
`if((h3+k3)<0||(h3+k3)>5) ... else { m3=(h3+k3)/i3; g3=i3+(h3+k3); }`
`h3+k3` встречается 4 раза → посчитано **один раз** и переиспользовано. **Суть:** одинаковое
подвыражение не считают заново. (`-O2` делит умножением на «магическое» число, `-Os` — командой `idiv`.)

### 12. Вынесение инвариантного кода — ОПТИМИЗАЦИЯ НЕ СРАБОТАЛА (см. Часть разбор ниже)
`for(i4=0;i4<=2;i4++){ printf("Hello"); ivector2[i4]=j*k; }`
`j*k` не зависит от счётчика — методичка ждёт выноса из цикла. Но **ни `-O2`, ни `-Os` не вынесли**:
`j`,`k` глобальные, в цикле вызов `printf`, компилятор не может доказать, что вызов их не меняет.
**Суть:** оптимизация делается только когда компилятор **уверен**, что это безопасно.

### 13. Мёртвый код (функция dead_code)
`idead_store=a; if(0) printf(...);` → тело функции пустое (`ret`), вызов из `main` удалён.
**Суть:** недостижимый код (`if(0)`) и запись, которую никто не читает, удаляются.

### 14. Ненужный цикл (функция unnecessary_loop)
`x=0; for(i=0;i<5;i++) k5=x+j5;` → цикл убран, оставлено `i=5; k5=j5;`. **Суть:** тело цикла
не зависит от счётчика (одно и то же) → оставлен только итог.

### 15. Слияние циклов (loop_jamming)
Два цикла с одинаковым заголовком. Методичка ждёт слияния в один; GCC сделал больше: важен только
итог последней итерации → **оба цикла удалены**, оставлены финальные значения.

### 16. Разворот цикла (loop_unrolling)
`for(i=0;i<6;i++) ivector4[i]=0;` → две широкие записи (`0..3` и `4..5`) + `i=6`.
`-O2` ещё и **встраивает** функцию в `main` (без вызова), `-Os` оставляет `call`. **Суть:** цикл
заменён прямой последовательностью записей.

### 17. Сжатие цепочки переходов (jump_compression)
`goto end_1`, где `end_1` сам содержит `goto beg_1` → один прямой переход на `beg_1`.
`-O2` удаляет пустой вызов из `main`, `-Os` сохраняет. **Суть:** цепочка из двух прыжков сжата в один.

**Три «фишки» для защиты** (где интересно): блок 4 (упрощения идут даже на `-O0`),
блок 12 (вынос не сработал из-за `printf` и глобальных `j`,`k`), блок 15 (циклы не слиты, а удалены).

## Часть 7. Практика: прочитай и скажи, что происходит

**1.**
```asm
mov  eax, 5
add  eax, 3
```
→ положили 5 в eax, прибавили 3. `eax = 8`.

**2.**
```asm
mov  eax, DWORD PTR x[rip]
cmp  eax, 10
jl   .L1
```
→ взяли переменную `x` в eax; если `x < 10` — прыгнуть на `.L1`. То есть `if(x<10) goto L1;`.

**3.**
```asm
xor  eax, eax
```
→ `eax = 0`. (Число, «исключающе-сложенное» само с собой, даёт 0. Так обнуляют регистр — короче и быстрее, чем `mov eax,0`.)

**4.**
```asm
lea  eax, [rdi + rdi*2]
```
→ `eax = rdi × 3` (rdi + rdi×2). Умножение на 3 одной дешёвой командой.

**5.**
```asm
mov  eax, DWORD PTR j5[rip]
sal  eax, 2
mov  DWORD PTR k2[rip], eax
```
→ взяли `j5`, сдвинули влево на 2 (= ×4), записали в `k2`. Это `k2 = j5 * 4`.

**6.**
```asm
.L2:
mov  DWORD PTR [rax], 5
add  rax, 4
cmp  rax, rdx
jne  .L2
```
→ цикл: записать 5 туда, куда смотрит указатель `rax`; сдвинуть указатель на 4 байта; если не
дошли до конца `rdx` — повторить. То есть заполнение массива пятёрками через «шагающий указатель».

## Часть 8. Вероятные вопросы и короткие ответы

**Сколько регистров и какие?**
Общего назначения: **8 в 32-битном** (`eax ebx ecx edx esi edi ebp esp`), **16 в 64-битном**
(те же, но `r..` + `r8…r15`). Плюс `rip` (указатель команды), `rflags` (флаги), `xmm0…15` (дробные).

**Что делает `mov` / `lea` / `cmp` / `jmp`?**
`mov` — копирует значение. `lea` — вычисляет **адрес** (или делает арифметику ×3,×5 за одну команду),
в память не лезет. `cmp` — сравнивает, выставляет флаги. `jmp` — безусловный прыжок на метку.

**Как работает связка `cmp` + `jl`/`jg`?**
`cmp A,B` считает `A−B` и записывает результат во **флаги** (ZF — равно, SF — знак, OF — переполнение).
Условный переход (`jl`,`jg`,`je`…) читает флаги и прыгает. `cmp eax,2; jle .L` = `if(eax<=2) goto L;`.

**Чем регистр лучше переменной в памяти?**
Регистр внутри процессора — доступ мгновенный; память снаружи — дольше. Компилятор держит частые
значения в регистрах, чтобы реже ходить в память → быстрее. (На `-O0` он каждый раз пишет в память
и читает заново, на `-O2` держит в регистре.)

**Что делает оптимизирующий компилятор в блоке N?**
См. Часть 6 — по каждому блоку одной фразой.

**Чем `-O0`, `-O2`, `-Os` отличаются?**
`-O0` — без оптимизаций (для отладки, медленно). `-O2` — под скорость (обычный выбор). `-Os` — под
размер (мало памяти). `-O1` — лёгкая, среднее. Размеры нашего кода: `-O0` 1780, `-O2` 1028, `-Os` 868 байт.

**Почему `j*k` не вынесли из цикла (блок 12)?**
`j`,`k` глобальные, в цикле `printf` — компилятор не может доказать, что вызов их не меняет,
и пересчитывает каждый проход. Будь они локальными — вынес бы.

**Что за предупреждение про `ivector5`?**
Индекс `i*2+3` на 49-м проходе убегает за границу массива (100 ячеек). Компилятор заметил это,
когда анализировал переменную индукции цикла (блок 8).
