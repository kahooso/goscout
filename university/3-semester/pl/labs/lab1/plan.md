## Команды (для твоего терминала)

Открыть **обычный** терминал (PowerShell или cmd) в папке лабы. Убедиться, что зовётся
настоящий GCC, а не clang:

```
C:\mingw64\bin\gcc --version      # должно быть: gcc (…MinGW…) 15.2.0
```

Листинги (пункты 3, 4, 7):

```
C:\mingw64\bin\gcc -S -O0 -masm=intel -fverbose-asm OPTBENCH.c -o optbench_O0.s
C:\mingw64\bin\gcc -S -O2 -masm=intel              OPTBENCH.c -o optbench_O2.s
C:\mingw64\bin\gcc -S -Os -masm=intel              OPTBENCH.c -o optbench_Os.s
```

- `-S` — остановиться на ассемблере, не доводить до `.exe` (получаем `.s` — листинг).
- `-O0` — без оптимизаций (как написано в коде). `-O2` — оптимизация по скорости.
  `-Os` — по размеру. `-masm=intel` — синтаксис как в примере методички (`DWORD PTR x[rip]`).
- `-fverbose-asm` — дописывает в листинг комментарии `# переменная`, видно, что к чему.

Размеры бинарников (пункт 7) — сравнивать объектные файлы, там нет общего кода запуска:

```
C:\mingw64\bin\gcc -O2 -c OPTBENCH.c -o optbench_O2.o
C:\mingw64\bin\gcc -Os -c OPTBENCH.c -o optbench_Os.o
C:\mingw64\bin\size optbench_O2.o optbench_Os.o      # размер секций text/data/bss
```

`size` показывает размер секции `.text` (код) — это честное сравнение «скорость vs размер».

> Предупреждения `old-style function definition` — норма: `OPTBENCH.c` написан в старом
> K&R-стиле. На листинг не влияют.

## Карта блоков оптимизации в OPTBENCH.c

Каждый блок выделен комментарием. В `-O0` они идут по порядку, в `-O2` многие исчезают
или сливаются — это и есть материал для таблицы. Строки — по `gostudy-materials/3-semester/pl/OPTBENCH.c`.

### В функции `main`

| # | Блок (комментарий в коде) | Строки | Что должен сделать компилятор |
|---|---------------------------|--------|-------------------------------|
| 1 | Отказ от циклов | 54–57 | развернуть `for(i<3)` в 3 присваивания (или memset) |
| 2 | Переприсваивание | 59–64 | `i2=5; j4=6; i2=j4;` → мёртвые присваивания убрать |
| 3 | Размножение констант и копий | 65–79 | подставить константу `j4=2` прямо в сравнения |
| 4 | Свёртка констант, арифм. тождества, лишние load/store | 81–108 | `1+2`→`3`, `i+0`→`i`, `i/1`→`i`, `i*1`→`i`, `i*0`→`0` на этапе компиляции |
| 5 | Лишнее присваивание | 110–115 | `k3=1; k3=1;` → одно |
| 6 | Снижение мощности | 117–123 | `*2` → сдвиг/сложение, `4*j5` дешевле |
| 7 | Простой цикл (do-while 10000) | 125–135 | цикл остаётся, но тело оптимизируется |
| 8 | Управление переменной индукции цикла | 137–141 | `i*2+3` считать приращением, а не умножением каждый раз |
| 9 | Глубокие подвыражения | 143–150 | `if/else` с общим `i5+i2` |
| 10 | Константный адрес / копии и регистры | 152–161 | адрес `ivector[const]` вычислить сразу; повтор `ivector[i2]=2` — один раз |
| 11 | Удаление общих подвыражений (CSE) | 164–173 | `h3+k3` посчитать один раз, переиспользовать |
| 12 | Вынесение инвариантного кода из цикла | 175–183 | `j*k` не зависит от `i4` → вынести за цикл |
| 13 | Вызов функции с аргументами → `dead_code` | 185–189 | тело под `if(0)` — мёртвый код, убрать |
| 14 | Вызов функции без аргументов → `unnecessary_loop` | 191–195 | цикл с постоянным телом убрать |
| 15 | `loop_jamming` (слияние циклов) | 197–198 | два цикла с одним заголовком слить |
| 16 | `loop_unrolling` (разворот цикла) | 199 | цикл инициализации развернуть / заменить |
| 17 | `jump_compression` (сжатие переходов) | 200 | цепочку `goto` заменить прямым переходом |

### Отдельные функции (демонстрируют конкретную оптимизацию)

| Функция | Строки | Идея |
|---------|--------|------|
| `dead_code` | 211–220 | недостижимый код (`if(0)`) и лишнее присваивание не должны породить код |
| `unnecessary_loop` | 230–238 | тело цикла не зависит от счётчика → цикл не нужен |
| `loop_jamming` | 247–254 | два цикла с одинаковым заголовком → один |
| `loop_unrolling` | 265–270 | инициализация массива → без цикла |
| `jump_compression` | 279–300 | `goto end_1; … end_1: goto beg_1;` → прямой переход на `beg_1` |
