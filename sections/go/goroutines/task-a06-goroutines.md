# Task-06: Параллельный обработчик задач

## Задание

**Файл:** `sections/go/goroutines/goroutines.go`
**Тесты:** `sections/go/goroutines/goroutines_test.go`

Написать функцию `runAll(tasks []string, fn func(string))`:
- Запускает одну горутину на каждый элемент `tasks`
- Каждая горутина вызывает `fn(task)` для своего элемента
- Main дожидается завершения всех горутин через `sync.WaitGroup`
- Имя задачи передавать параметром в горутину (не через замыкание)

В `main` — список серверов, `runAll` с функцией которая печатает `"checking: " + name`.

Тесты: 2 кейса — пустой слайс и несколько элементов; счётчик вызовов через `sync/atomic`.

---

## Моё решение

Написал `runAll` с `sync.WaitGroup` внутри. На каждую итерацию range: `wg.Add(1)`, затем
запуск анонимной горутины с параметром `v string` (не через замыкание). Внутри горутины:
`defer wg.Done()` первой строкой, затем вызов `fn(v)`. После цикла — `wg.Wait()`.

В тестах: `var counter int64`, передаю в `runAll` функцию с `atomic.AddInt64(&counter, 1)`,
после — проверяю `counter == tc.want`.

---

## Ошибки и трудности

- `defer wg.Done()` поставил после `fn(v)` — ошибка: если `fn` паникует, defer не успеет зарегистрироваться и счётчик не уменьшится → deadlock. Исправил: перенёс на первую строку горутины.
- Общая картина горутины/каналы/планировщик/рантайм пока не сложилась в единое целое — нужна практика.
- `defer` как концепция была новой — понял что это гарантированный cleanup, но нужно больше примеров.
- Написал `int64(0)` и `int64(3)` в тесте — лишние касты: тип выводится из поля структуры.

---

## Что бы сделал иначе

Сразу ставить `defer wg.Done()` первой строкой — как правило, без исключений.

---

## Ключевые пакеты и паттерны

- `sync.WaitGroup` — счётчик горутин; `Add(n)` до `go`, `Done()` в горутине, `Wait()` в main
- `defer wg.Done()` — первая строка горутины, гарантирует выполнение даже при панике
- Передача переменной цикла параметром `go func(v string){}(v)` — фиксирует значение в момент запуска
- `sync/atomic.AddInt64(&counter, 1)` — атомарный счётчик, безопасен из нескольких горутин
- `_` в сигнатуре функции `func(_ string)` — явный сигнал что параметр намеренно игнорируется
