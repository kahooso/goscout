# Task-03: Парсер CSV-логов

## Задание

**Файл:** `sections/go/logparse/logparse.go`
**Тесты:** `sections/go/logparse/logparse_test.go` ✅ написаны в следующей сессии (отдельный урок по `testing`)

Написать программу-парсер логов в CSV-формате.

Входные данные захардкожены в `csvLog`. Формат: `timestamp,level,message`.

Реализовать:
1. `parseLogs(lines []string) []LogEntry` — парсинг строк в структуры
2. `countByLevel(logs []LogEntry) map[string]int` — счётчик по уровню
3. `countByMessage(logs []LogEntry) map[string]int` — счётчик по сообщению
4. `topMessages(mTop map[string]int, n int) []string` — топ-N сообщений по убыванию

---

## Моё решение

Вынес подсчёт сообщений в отдельную функцию `countByMessage` и передал результат
в `topMessages` как параметр — так мап остаётся доступной в `main` для вывода частот.

В `topMessages`: извлёк ключи из мап в слайс, отсортировал через `sort.Slice` с `>`,
защита от `n > len(top)` через явную проверку.

---

## Ошибки и трудности

- `make([]string, n)` вместо `make([]string, 0, n)` — создал слайс с n пустыми строками,
  `append` добавлял ключи ПОСЛЕ них. Вывод содержал пустую строку `": 0"`.
  Разница: первый аргумент — len (заполняется нулями), второй — cap (резервирует место).
- Условие защиты `if len(top) <= n { return top[:n] }` — логика перепутана:
  именно в этой ветке и происходила паника. Правильно: `if n > len(top) { return top }`.
- `var top []string = make(...)` — C-стиль, в Go просто `:=`.
- nil-checks в начале функций — лишние: `for range nil` в Go работает (0 итераций).
- `csv_log`, `CSV_SEP`, `m_top` — snake_case и ALL_CAPS не приняты в Go. Исправлено на `csvLog`, `csvSep`, `mTop`.

---

## Что бы сделал иначе

Сразу `make([]string, 0, len(mTop))` — не путать len и cap как первый аргумент.
Условие защиты писать как `n > len(slice)` — читается как "запросили больше чем есть".

---

## Ключевые пакеты и паттерны

- `strings.Split(s, sep)` — разбивка по разделителю, включая пустые строки
- `map[string]int` + `m[key]++` — идиоматичный счётчик
- `make([]T, 0, cap)` — pre-allocate с пустым len: `append` с первого элемента
- `sort.Slice` с `>` — убывание; `<` — возрастание
- Передача map в функцию — копируется указатель, таблица общая (в отличие от slice)
- `top[:n]` — срез возвращает новый заголовок, данные не копируются

---

## Вопросы сессии (разобраны)

- Одиночные кавычки `''` в Go — это `rune` (int32), не строка. Raw строки через `` ` ``.
- `make` — полиморфный для slice/map/channel, параметры свои для каждого, проверяет компилятор.
- Ошибка компиляции (до запуска) vs паника (в рантайме, segfault в C).
- camelCase везде: экспортируемое с большой буквы, приватное с маленькой.
- Передача слайса в функцию: заголовок копируется, элементы общие, размер нет.

## Ошибки при написании тестов (следующая сессия)

- `t.Errorf("не правильно!")` — при провале ничего не видно. Нужно `got %v, want %v`.
- `got := topMessages(tc.top, 2)` — `n` захардкожен. Нужно добавить `n int` в struct кейса.
- В кейсе `"n < len(top)"`: `n=1`, `want` содержал оба элемента — функция права, тест неверен.
  Логика: если запросили 1 — вернуть 1, не все. `want` исправлен на `[]string{"Hey there"}`.
- `testing.T` — struct, не интерфейс. `t.Fatalf` — не паника, а `runtime.Goexit()`.
