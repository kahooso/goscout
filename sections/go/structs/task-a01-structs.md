# Task-01: Структуры и методы в Go

## Задание

**Файл:** `sections/go/structs/main.go`

Написать тип `Task` — простая модель задачи из todo-списка:

```
Поля:
- ID     int
- Title  string
- IsDone bool
```

Что реализовать:
1. Конструктор `NewTask(id int, title string) *Task`
2. Метод `Complete()` — помечает задачу выполненной (pointer receiver)
3. Метод `String() string` — возвращает строку вида `[x] 1. Купить хлеб` или `[ ] 2. Написать код`
4. Функцию `PrintAll(tasks []*Task)` — печатает все задачи через fmt

---

## Моё решение

Написал тип `Task` с тремя полями. Конструктор `NewTask` возвращает `*Task`.
`Complete()` — pointer receiver, меняет `IsDone`. `String()` — value receiver, только читает.
Использовал `strconv.Itoa` изначально для форматирования ID, потом заменил на `fmt.Sprintf`.
Добавил nil-checks в оба метода — по итогам ревью убрал как неидиоматичные.
Добавил лишний метод `Print()` который не был частью задания — помечен в коде как ЛИШНЕЕ.

---

## Ошибки и трудности

- `var tasks []*Task = []*Task{...}` — C-стиль, избыточен. Заменено на `:=`
- `IsDone: false` в конструкторе — шум, нулевое значение `bool` в Go уже `false`
- Nil-checks в бизнес-методах — не принято в Go; защита от nil здесь перекладывает ответственность не туда
- `Print()` добавлен по инерции — лишний публичный метод без использования
- Формат `String()` изначально не совпадал с заданием (`0 [x] Купить хлеб` вместо `[x] 0. Купить хлеб`)
- **Модель памяти слайсов** — не до конца понята. `[]*Task` vs `[]Task` vs `[][]Task` vs `*[]Task` требует отдельного разбора в следующей сессии с аналогиями C и указателями

---

## Что бы сделал иначе

Сразу использовать `fmt.Sprintf` вместо `strconv.Itoa` — в Go строки форматируют через fmt, не через strconv.

---

## Ключевые пакеты и паттерны

- `fmt` — `Sprintf` для форматирования строк; `Println` автоматически вызывает `String()` если тип его реализует
- Паттерн конструктора: `func NewT(...) *T { return &T{...} }`
- Pointer receiver — для методов, которые меняют поля
- Value receiver — для методов, которые только читают
- Интерфейс `fmt.Stringer` — неявно реализуется через метод `String() string`
