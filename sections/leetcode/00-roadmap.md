# LeetCode — план и прогресс

Параллельный трек: закрепление базы (slices, maps, pointers, strings) на задачах
в формате собеседования. **Не** основная линия обучения — пятиминутки на удержание формы.
Язык — Go, пакет = имя задачи (не `main`), запуск через `go test`.

## Как это работает

- **Источник плана и прогресса — этот файл.** Скилл `leetcode` ищет первую `[ ]` и советует её.
- **Прогресс определяет отметка `[x]`**, а не наличие папки. `[x]` = решено и записано.
- **Папка = хранилище, не статус.** Каталог `<slug>/` создаётся при выдаче задания —
  туда кладётся заготовка. Папка есть, отметки нет → задача в работе.
- Каталоги на `_` (`_TEMPLATE/`) — служебные, не задачи.
- Одна задача = одна папка = `<имя>.go` + `<имя>_test.go` + `notes.md`.

## Правила прохождения

- Не чаще ~1 задачи на 2–3 задания основного блока — трек не должен отвлекать от линии.
- Застрял на 25–30 минут → разобрать решение, понять, и **решить заново без подсказки через день**.
- Считаем паттерны, а не задачи: цель — узнавать «это two-pointers», а не «нарешал 300».
- Не брать задачу на паттерне, который ещё не проходили в основном блоке.
